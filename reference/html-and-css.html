Why this doc exists separately

Most tutorials teach "the flexbox shortcut" or "CSS Grid in 15 minutes." HTML & CSS starts at what is the platform contract that every CSS rule manipulates? It is a distinct discipline with its own history, algorithms, and failure modes — not "styling" as decoration, not "Tailwind vs CSS-in-JS" as a religion, not "semantic HTML" as a checklist. This doc captures it as a first-class engineering concern: the declarative, cascading, accessible-by-default rendering substrate that UI/UX decisions materialize on, the Developer Loop executes against, and JavaScript manipulates. If you've ever debugged a layout shift, a specificity war, a dark-mode breakage, or a screen reader that reads "button" on a

— this is the layer you missed.

How to use this doc

Reading order: standalone. Cross-links:

  • Upstream to UI/UX & Web Design — UI/UX decides what the rendered thing should be; HTML & CSS is the substrate it renders on. The state visibility matrix (the UI/UX worked example) maps directly to HTML states (aria-busy, aria-invalid) and CSS states (:hover, :focus-visible, [data-loading]).
  • Downstream to How Developers Think When Building a Frontend Feature — the developer loop builds components using HTML elements and CSS rules as primitives. The loop's "shape" decisions (component API, state shape) are constrained by what the platform makes expressible.
  • Cross-cutting to JavaScript: The Language — JS manipulates the DOM (HTML's in-memory tree) and the CSSOM (CSS's in-memory stylesheet). This doc explains what those trees are and how the cascade resolves before JS touches them.
  • Cross-cutting to System Design — rendering strategy (SSR, RSC, Islands, SPA) is a decision about who emits the initial HTML and when CSS arrives. The platform contract (HTML parsing, CSS blocking, font loading) is the ground truth every strategy negotiates with.
  • Context from Frontend Camps Survey — each camp (React, Vue, Svelte, Solid, Qwik, Astro) is a different abstraction over the same substrate. The substrate doesn't change; the abstraction's leakiness does.
  • Reference: Glossary — shared vocabulary across all reference docs.

The two-tree answer to "what is the web platform?"

  • The DOM (Document Object Model) — the parsed HTML tree. Elements, attributes, text nodes. The structure the browser exposes to JavaScript. document.querySelector('article') returns a DOM node.
  • The AOM (Accessibility Object Model) / Accessibility Tree — a parallel tree derived from the DOM, filtered for semantics.

CSS operates on a third structure: the Render Tree (DOM + computed styles → boxes). The cascade, layout, paint, and composite all happen here. Three trees, one source: the HTML you write.

Definition — what HTML & CSS is and what it is not

What it is

HTML & CSS is the declarative, cascading, accessible-by-default rendering contract of the web platform. It produces decisions — not imperative instructions — that determine:

  • Document structure & semantics — what elements exist, how they nest, what they mean (
    vs
    vs
    ). The DOM is the parse result; the AOM is the semantic projection.
  • The cascade algorithm — how competing declarations resolve: origin (user agent / user / author), importance (!important), specificity, source order, scope proximity, cascade layers. Deterministic, inspectable, non-imperative.
  • Box model & formatting contexts — every element generates boxes (content, padding, border, margin). Boxes participate in formatting contexts (normal flow, flex, grid, table, ruby). Layout is constraint-solving on boxes.
  • Visual formatting & theming — color, typography, spacing, motion, shadows, borders, filters, blend modes. Expressed as computed values on boxes.
  • State exposure — pseudo-classes (:hover, :focus-visible, :disabled, :valid, :placeholder-shown), attribute selectors ([aria-busy="true"], [data-state="loading"]), container queries (@container). The platform exposes state; CSS selects it.
  • Responsive & intrinsic sizing — media queries (@media), container queries (@container), min()/max()/clamp(), fit-content, min-content, max-content. Layout adapts to constraints without JS.
  • Accessibility as default — semantic HTML is the accessibility API. ,
    /, aria-* only when semantics gap exists. WCAG 2.2 AA baseline.

These decisions are expensive to change later. A CSS refactor touches every component. An HTML semantics audit touches every template. The earlier platform decisions enter, the cheaper the system.

Why this survived. The web platform survived every attempt to replace it (Flash, Silverlight, Java Applets, native apps) because its contract is uniquely resilient: a declarative document that renders everywhere, degrades gracefully, and is inspectable by default. Each milestone solved a real pain: CSS 1 separated structure from presentation (ending the tag era), Flexbox killed the clearfix hack, Grid killed the float-based holy grail, Container Queries killed viewport-query workarounds, and Cascade Layers killed the !important escalation war. The platform absorbs patterns that were previously polyfilled or framework-specific — nesting, scoping, anchor positioning — because the constraint inversion pattern repeats: when the dominant constraint shifts, a new platform feature absorbs it.

Evolution — constraint inversions across the platform

The core idea — a declarative document that renders everywhere — did not change. What changed is the dominant constraint, and the platform feature that absorbed it:

Dominant constraintWinning platform featureWhy it fit
No layout at all (1991–1996)HTML tables + presentational attributesTables were the only grid. , bgcolor, align = author control. Semantic pollution accepted.
Separation of concerns (1996–2003)CSS 1/2 + DOCTYPE switchingStylesheets external, cascade resolves conflicts. "Standards mode" = predictable box model. Float-based layout (holy grail, clearfix).
Rigid float layouts break on content change (2003–2012)Flexbox (one-dimensional)Flex solves "center vertically," "equal height columns," "push footer down." One axis, content-driven. No more clearfix.
Two-dimensional layout still hard (2012–2018)CSS Grid (two-dimensional)Grid solves "row + column simultaneously," "overlap," "named areas," "intrinsic tracks (minmax, auto-fit)." Layout as constraint system, not hack.
Viewport queries can't express component-level responsive (2018–2022)Container QueriesA card in a sidebar vs main column needs different breakpoints. @container queries the parent's size, not viewport. Component owns its responsive logic.
Specificity wars + third-party CSS collisions (2019–2023)Cascade Layers (@layer)Layers = explicit origin ordering: @layer reset, base, components, utilities. Third-party CSS in its own layer. No more !important escalation.
Authoring ergonomics vs platform verbosity (2020–2024)Nesting, :has(), Custom Properties, @propertyNesting = less selector repetition. :has() = parent selector (finally). @property = typed custom properties (animation, validation). The platform absorbs preprocessor features.
JS-heavy interactions (tooltips, popovers, transitions) (2023+)Anchor Positioning, View Transitions, Popover API, @starting-styleTooltip positioning without JS math. Cross-document transitions without SPA. Declarative popovers. The platform absorbs common JS patterns.

The pattern repeats: when the dominant constraint changes (no layout → separation → flexible 1D → flexible 2D → component-responsive → collision-free cascade → ergonomic authoring → declarative interaction), the old feature's ergonomics become friction and a new platform feature absorbs the constraint.

Underlying theory — the algorithms the platform runs

Theory / AlgorithmSpec / OriginWhat the platform does with it
HTML Parsing Algorithm WHATWG HTML Living Standard — "The HTML Parser" Tokenization → tree construction. Handles malformed markup deterministically (adoption agency algorithm, foster parenting). The DOM you get is specified, not browser-dependent.
CSS Cascade Algorithm CSS Cascading and Inheritance Level 5 Origin (UA/user/author) → Importance (!important) → Specificity (ID/Class/Type) → Source Order → Scope Proximity → Layer Order. Deterministic, inspectable in DevTools "Computed" tab.
CSS Specificity Calculation CSS Selectors Level 3/4 (a,b,c) = (ID count, Class/Attribute/Pseudo-class count, Type/Pseudo-element count). #id .class:hover = (1,2,0). Higher wins. Not base-10; (0,11,0) < (1,0,0).
Box Model & Box Tree Construction CSS Box Model Level 3/4, CSS Display Level 3 Every element → principal box (content/padding/border/margin). display sets outer (block/inline/flex/grid) and inner (formatting context) display types. box-sizing: border-box changes which box width/height applies to.
Formatting Contexts CSS Display Level 3, CSS Flexbox, CSS Grid BFC (Block Formatting Context): floats, margins, clears. Flex: main/cross axis, alignment, distribution. Grid: tracks, lines, areas, auto-placement. Each context has its own layout algorithm.
Intrinsic Sizing & min/max-content CSS Sizing Level 3/4 min-content = smallest without overflow. max-content = largest without wrapping. fit-content(limit) = clamp(min-content, limit, max-content). Grid minmax(), auto-fit, auto-fill use these.
Accessibility Tree Construction W3C ARIA in HTML, HTML AAM (Accessibility API Mappings) DOM → AOM: role, name, description, state, relations.
Rendering Pipeline: Style → Layout → Paint → Composite CSSOM, Blink/WebKit/Gecko internals Style: cascade → computed values. Layout: box tree → geometry (constraint solving). Paint: display lists (draw commands). Composite: layers → GPU. transform/opacity = composite-only (cheap). Layout = expensive.
Progressive Enhancement / Principle of Least Power Tim Berners-Lee, Noah Mendelsohn (W3C TAG) Use the least powerful language that solves the problem: HTML (declarative structure) → CSS (declarative style/layout) → JS (imperative behavior). Each layer works without the next. Resilience by design.
CSS Custom Properties & @property CSS Custom Properties Level 1/2, CSS Properties and Values API Custom properties inherit, cascade, fallback (var(--x, fallback)). @property registers type (, ), initial-value, inherits: true/false. Enables animation, validation, typed OM.

Anti-pattern: Writing CSS that fights the platform. The cascade, inheritance, formatting contexts, and pseudo-classes are not bugs to work around — they are the platform's primitives. Working with them (semantic HTML, logical properties, container queries, cascade layers) is always smaller and more robust than working against them (utility frameworks that strip semantics, JS layout libraries, !important wars).

---

Like UI/UX & Web Design, System Design, and API Design, HTML & CSS is a rhythm, not a structured algorithm. It fails the three algorithm tests:

  • Inputs aren't predefined. You don't know all future content, viewport sizes, user preferences (dark mode, reduced motion, high contrast), or browser capabilities when you write the first rule. The platform discovers them at runtime.
  • Steps aren't deterministic. There is no rule that says "now reach for Grid." You choose Grid when the design requires two-dimensional alignment with intrinsic tracks — a judgment call. @container vs @media is a context judgment, not a predicate.
  • No fixed termination. "Done" means "the component renders correctly across the support matrix (browsers, viewports, modes, a11y tree) and the cascade is inspectable without !important." That is a judgment, not a predicate. The platform evolves; the component iterates.

This is why HTML & CSS resists checklists that pretend to be complete. A checklist assumes you know the final content and context; the rhythm assumes you know what's missing for the context you have — a platform/engineering judgment.

The "Design Tokens → CSS Custom Properties" rhythm hack. Design tokens (W3C DTCG format) compile to CSS custom properties. The platform's cascade + inheritance + fallback + @property typing is the runtime for tokens. A token change = one CSS variable change = instant propagation to every component. No build step, no redeploy. It's a velocity multiplier — useful when the token system is alive, dangerous when tokens become a bureaucracy that forbids per-component deviation.

Form checklist

  • Every input has a real label (click targets it, name comes from it).
  • Group related fields with fieldset + legend.
  • Use correct types (email, tel, url, number, search, date, password) — right on-screen keyboard, right validation.
  • Use autocomplete values (email, name, country, …) for autofill.
  • Use required, min/max, minlength/maxlength, pattern where helpful.
  • Use inputmode and enterkeyhint for mobile keyboards.
  • Never disable zoom, and never suppress validating of a field the user hasn't touched: validate on blur/submit, and use :user-invalid for after-interaction errors — matched in UI/UX forms.
  • Associate errors with the field via aria-describedby.
  • Preserve user input after a validation failure.

Principles — the shared constants

Across every methodology, eight principles hold (synthesized from the HTML/CSS specs, WCAG, and platform invariants):

  1. Semantic HTML is the accessibility API.
  2. The cascade is public policy, not personal taste. User stylesheets win. !important in author CSS is a policy violation — it blocks user agency (high contrast, custom fonts, zoom). Use cascade layers, specificity, and source order instead.
  3. Layout system choice is irreversible-ish per formatting context root. A flex container's children are flex items. A grid container's children are grid items. You cannot mix formatting contexts on the same children. Choose at the container; the children obey.
  4. Progressive enhancement is a contract, not a suggestion. HTML works without CSS. CSS works without JS. JS enhances, never gates. The platform guarantees this if you don't break it (e.g.,
  5. Tokens over magic numbers. padding: var(--space-4) not padding: 16px. color: var(--color-primary) not color: #3b82f6. Tokens enable dark mode, density, theming, and cross-platform sync. Magic numbers guarantee drift.
  6. Performance is a platform feature you configure. , font-display: swap, content-visibility: auto, will-change (sparingly). The platform doesn't optimize for you; it exposes knobs. Measure (CLS, LCP, INP), then turn knobs.
  7. State lives in attributes, selects in CSS. [aria-busy="true"], [data-state="loading"], :disabled, :focus-visible. JS toggles attributes; CSS selects states. No JS-in-CSS (no style="..." from JS), no CSS-in-JS state logic.
  8. Respect user preferences by default. @media (prefers-reduced-motion: reduce) disables non-essential animation. @media (prefers-contrast: more) boosts contrast. @media (prefers-color-scheme: dark) swaps tokens. The platform exposes preferences; you honor them.

Step 4 — Dark mode, RTL, reduced motion: zero extra CSS

  • Dark mode — tokens swap via @media (prefers-color-scheme: dark). OKLCH preserves perceptual lightness; no "vibrating" brand colors.
  • RTL — logical properties (margin-inline-start, padding-inline-end, border-inline-start) mirror automatically. Flex/Grid honor dir="rtl" on . The badge stays leading; footer actions reverse.
  • Reduced motion — @media (prefers-reduced-motion: reduce) zeros motion tokens. Transitions become instant. No vestibular triggers.
  • High contrast / forced colors — @media (forced-colors: active) disables backgrounds/shadows; system colors take over. border: 1px solid CanvasText ensures visibility.

The practitioner critique (1998–present)

HTML & CSS has faced serious critique from the platform community:

  • Jeffrey Zeldman / Eric Meyer (Web Standards Project, 1998–2008) — "Designing with Web Standards": presentational HTML (, tables for layout) is technical debt. Separation of concerns is not optional. The cascade is a feature, not a bug.
  • Jeremy Keith (Resilient Web Design, 2016) — Progressive enhancement is the web's superpower. Every layer (HTML, CSS, JS) must work without the next. The platform is resilient by default; we break it.
  • Harry Roberts (CSS Wizardry, 2010–present) — Specificity is the enemy of scale. Flat specificity (BEM, utility) beats architectural CSS. !important is a code smell. ITCSS / Cascade Layers formalize this.
  • Una Kravets / Adam Argyle / Bramus (Chrome DevRel, 2020–present) — The platform has absorbed the patterns you polyfill. Container queries, cascade layers, nesting, :has(), anchor positioning — stop shipping JS for what CSS now does.
  • Rachel Andrew / Jen Simmons (CSS WG, 2015–present) — Intrinsic web design: layout from content out, not viewport in. minmax(), auto-fit, fit-content are the new primitives. Grid + Flexbox + Flow = complete system.
  • Miriam Suzanne (OddBird, CSS WG, 2020–present) — Cascade Layers solve the "third-party CSS collision" problem natively. @scope solves "component scoping without Shadow DOM." The cascade is a designed system, not a battlefield.

Does the component work without JS (forms submit, links navigate, details/summary toggles)?Stop. JS as enhancement, not gate.
+
Are all colors, spacing, typography, motion, shadows defined as CSS Custom Properties (tokens) — no magic numbers?Stop. Dark mode breaks, density breaks, theming breaks, drift guaranteed. One token file = single source of truth.
Does dark mode work via @media (prefers-color-scheme: dark) token swap — no filter: invert hack?Stop. Images invert, brand vibrates, shadows disappear. OKLCH tokens preserve perceptual lightness.
Does RTL work via logical properties (margin-inline, padding-inline, border-inline) and native flex/grid mirroring — no manual overrides?Stop. Manual RTL CSS is technical debt. Logical properties + dir="rtl" on = platform does it.
Does the component respect prefers-reduced-motion (non-essential animation disabled via motion tokens)?Stop. Vestibular triggers ship by default. Motion tokens zeroed in @media (prefers-reduced-motion: reduce).
Is there a visible :focus-visible ring on every interactive element (outline, not box-shadow)?Stop. Keyboard users lose position. outline: 2px solid var(--color-primary); outline-offset: 2px.
Does the component have no layout shift above the fold (CLS = 0) — explicit sizes, aspect-ratio, font-display: swap?Stop. CLS = user frustration. Reserve space for images, ads, fonts. aspect-ratio on media, font-display: swap on fonts.
Does the component pass manual screen reader test (VoiceOver/NVDA) — announces correct role, name, state?Stop. AOM diff catches what axe misses. Test: tab through, hear heading structure, button/link roles, form labels.
