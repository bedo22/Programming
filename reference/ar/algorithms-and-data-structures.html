التحليل المطفأ — الفكرة الوحيدة المفاجئة: عملية تكون مكلفة أحيانًا تُقاس معدَّلةً على مدى استدعاءات كثيرة. الدفع إلى مصفوفة ديناميكية هو «O(1) مطفأ»: معظم الإضافات O(1)، وإعادة الحجم العرضية (المضاعفة) O(n)، لكن المضاعفة تعني أن كل عنصر يُنسخ على الأكثر ~log n مرة — لذا يكون المتوسط ثابتًا. حين «يبدو» حل ما O(n²) لكنه ينجح، فغالبًا أنت تنظر إلى سلوك مطفأ (مثلًا سلسلة تُبنى بـ += في حلقة، أو مسح بمؤشرين يدخل فيه كل عنصر مرة واحدة).

مفاضلة الفضاء والزمن: كل خدعة «سريعة» تقريبًا تشتري وقتًا بذاكرة — خرائط التجزئة تخزّن النتائج، وجداول البرمجة الديناميكية تخزّن الحالات، والمجاميع البادئة تحسب النطاقات مسبقًا. حين تقول المسألة «يجب أن تكون O(n)» وتعلق، السؤال الذي تسأله: «ما الذي يمكنني أن أتذكّره؟»

المصفوفات والسلاسل والتجزئة — الـ 80%

معظم مسائل المقابلات — ومعظم كود الإنتاج — هي هذه الهياكل الثلاثة. أتقن هذا القسم وستجتاز غالبية المسائل السهلة وكثيرًا من المتوسطة.

خرائط التجزئة والمجموعات — كيف يعمل O(1) فعلًا

  • الدواخل: يُجزَّأ المفتاح إلى دلو؛ تُعالَج التصادمات بالتسلسل (قائمة لكل دلو) أو بالعنونة المفتوحة. ادعاء O(1) يعتمد على بقاء معامل التحميل (المفاتيح ÷ الأدلاء) منخفضًا — لهذا تتغيّر أحجام خرائط التجزئة حين تمتلئ.
  • حين يتدهور O(1) إلى O(n): مفاتيح عدائية تُجزَّأ كلها في دلو واحد (هجوم معروف — بعض اللغات تعشّي التجزئة)، أو — في JS — الفخ الكلاسيكي باستخدام كائن كخريطة، فتحصل على تلوث النموذج الأولي أو مفاتيح مكرَهة إلى سلاسل (obj[1] وobj["1"] هما المفتاح نفسه). استخدم Map/Set لدلالات مفاتيح حقيقية.
  • النمط الذي يربح المسائل: «count occurrences» (خريطة تكرارات)، و«هل رأيت هذا من قبل؟» (مجموعة seen)، و«بحث المكمِّل» (عائلة two-sum: خزّن target - current وتحقّق منه في المرة التالية).

المؤشران — القالب

// sorted array: find the pair summing to target
let lo = 0, hi = arr.length - 1;
while (lo < hi) {
  const sum = arr[lo] + arr[hi];
  if (sum === target) return [lo, hi];
  sum < target ? lo++ : hi--;
}
return null;

متى ينطبق: مصفوفات مرتبة (مجاميع أزواج، إزالة التكرار، عائلات three-sum)، فحوصات المتناظرات، «عكس في المكان». الثابت: المؤشران يتحركان في اتجاه واحد فقط، فالعملكلّي O(n) — كل عنصر يُزار مرتين على الأكثر.

النافذة المنزلقة — القالب

// longest substring with no repeating characters
let seen = new Set(), left = 0, best = 0;
for (let right = 0; right < s.length; right++) {
  while (seen.has(s[right])) seen.delete(s[left++]);
  seen.add(s[right]);
  best = Math.max(best, right - left + 1);
}
return best;

متى ينطبق: عبارات «longest / contiguous / subarray» — أقصى مجموع لنافذة طولها k، سلسلة فرعية فيها على الأكثر k قيمة مميزة، أصغر نافذة. الشكل دائمًا: وسّع لليمين، وقلّص لليسار ما دام القيد منكسرًا، وسجّل الأفضل. O(n) مطفأ: اليسار واليمين يجتاز كلٌّ منهما مرة واحدة.

المجاميع البادئة

احسب مسبقًا prefix[i] = sum of elements 0..i-1، فكل مجموع سلسلة فرعية هو prefix[j+1] - prefix[i] في O(1). نمط الترقية: «استعلامات مجموع نطاقات» أو «مجاميع سلاسل فرعية تساوي k» تتحول إلى خريطة تجزئة لعدّادات البادئات — حركة «ما الذي يمكنني تذكّره؟» الكلاسيكية.

المكدسات وقوائم الانتظار والقوائم المترابطة — الأشكال

المكدس — نمط المكدس الرتيب

المكدس هو «أول ما يُتراجع عنه»، و«الأزواج المتطابقة»، و— القوة الخارقة في المقابلات — المكدس الرتيب: أبقِ المكدس متزايدًا (أو متناقصًا) بالحذف (pop) ما دام العنصر الجديد يكسر الترتيب. يعطيك ذلك «العنصر الأكبر التالي» في O(n):

// next greater element for each position, -1 if none
const out = new Array(nums.length).fill(-1), stack = [];
for (let i = 0; i < nums.length; i++) {
  while (stack.length && nums[stack[stack.length - 1]] < nums[i])
    out[stack.pop()] = nums[i];
  stack.push(i);
}
return out;

مسائل المكدس الكلاسيكية: أقواس صالحة (ادفع الفواتح، واحذف عند الغلّاقة، وتحقق من تطابق القمة)، وتقييم التعابير (مكدسان: قيم + معاملات)، ودرجات الحرارة اليومية، وأكبر مستطيل في المدرّج التكراري.

قائمة الانتظار — شريكة BFS

قائمة الانتظار «الأول داخلًا أول خارجًا» — شكل اجتياز العرض أولًا (BFS) وأي مسألة «معالجة بترتيب الوصول». في JS، مصفوفة مع shift() تكلف O(n)؛ لحلول الصحة-أولًا هذا مقبول، وللأداء استخدم مؤشر فهرس أو قائمة انتظار حقيقية.

القوائم المترابطة — نادرًا الإجابة، كثيرًا السؤال

  • قاعدة الصدق: في JS (ومعظم اللغات عالية المستوى)، المصفوفات تتغلب على القوائم المترابطة في كل شيء تقريبًا — محلية الكاش، والفهرسة، والذاكرة. مسائل القوائم المترابطة تُطرح لأنها تختبر انضباط المؤشرات والعودية، لا لأن كود الإنتاج يستخدمها كثيرًا.
  • عمليات أساسية يجب حفظها: العكس (تكرارية: ثلاثة مؤشرات — prev، curr، next)، وكشف الحلقات (سلحفاة وأرنب فلويد: بطيء +1، سريع +2، يلتقيان إذا وُجدت حلقة فقط)، وإيجاد المنتصف (تقنية الأرنب نفسها)، ودمج قائمتين مرتبتين (نمط الرأس الوهمي).
  • خدعة الرأس الوهمي: ابدأ كل خوارزمية قائمة كثيفة الإدراج بعقدة dummy قبل الرأس كي لا تحتاج حالتا «القائمة الفارغة» و«الإدراج من الأمام» معالجة خاصة. تزيل فئة كاملة من أخطاء الحالات الحدّية.

مثال محلول — كاش LRU

مسألة القوائم المترابطة الوحيدة التي هي أيضًا هيكل إنتاج حقيقي: كاش LRU (الأقل استخدامًا مؤخرًا) هو قائمة مترابطة مزدوجة للترتيب بالإضافة إلى خريطة تجزئة لبحث O(1) لكل عقدة. يجب أن يكونا get وput كلاهما O(1) — القائمة تعطي إزالة-ونقل-إلى-الأمام O(1)، والخريطة تعطي إيجاد O(1) — والإخراج هو «احذف الذيل». خدعة الرأس الوهمي تُبقي عمليات القائمة بلا حالات حدّية:

class LRUCache {
  constructor(cap) {
    this.cap = cap;
    this.map = new Map();            // key → node, for O(1) lookup
    this.head = { key: null, prev: null, next: null };  // most recent
    this.tail = { key: null, prev: null, next: null };  // least recent
    this.head.next = this.tail; this.tail.prev = this.head;
  }
  _remove(node) { node.prev.next = node.next; node.next.prev = node.prev; }
  _insert(node) {                    // splice right after the head (most recent)
    node.prev = this.head; node.next = this.head.next;
    this.head.next.prev = node; this.head.next = node;
  }
  get(key) {
    const node = this.map.get(key);
    if (!node) return -1;
    this._remove(node); this._insert(node);   // touch → most recent
    return node.value;
  }
  put(key, value) {
    if (this.map.has(key)) this._remove(this.map.get(key));
    const node = { key, value, prev: null, next: null };
    this.map.set(key, node);
    this._insert(node);
    if (this.map.size > this.cap) {      // evict the tail
      this.map.delete(this.tail.prev.key);
      this._remove(this.tail.prev);
    }
  }
}

الخلاصة: خريطة التجزئة وحدها لا تتتبع الحداثة، والقائمة وحدها لا تجد عقدة في O(1) — الزوجان هما بيت القصيد. تعرّف على «ذاكرة تخزين مؤقت بسعة محدودة» وستكون قد تعرّفت على هذا الشكل.

الأشجار والأكوام — التسلسلات الهرمية

الأشجار الثنائية — الاجتيازات أولًا

الاجتيازات هي نحو (grammar) كل مسألة شجرة؛ الأنماط الأربعة، محفوظة:

// recursive in-order — the shape of all three
function inorder(node, out = []) {
  if (!node) return out;
  inorder(node.left, out);
  out.push(node.val);
  inorder(node.right, out);
  return out;
}
  • الترتيب الأمامي (العقدة، اليسار، اليمين): نسخ/تسلسل شجرة، بادئة التعبير.
  • الترتيب الداخلي (اليسار، العقدة، اليمين): شجرة بحث ثنائية (BST) بترتيب داخلي هي مرتبة — الحقيقة الأكثر استخدامًا في مسائل الأشجار (تحقق من BST بفحص أن الاجتياز الداخلي تصاعدي).
  • الترتيب الخلفي (اليسار، اليمين، العقدة): أعمال الحذف/المعتمدة على الأطفال، وتقييم التعبيرات — احسب الأطفال أولًا ثم ادمج عند الأب.
  • ترتيب المستويات (BFS) بقائمة انتظار: «zigzag»، و«right side view»، و«min depth» — أي شيء يُصاغ مستوىً بمستوى.

بدائل تكرارية: المقابلات كثيرًا ما تمنع مكدس العودية الضمني للأشجار العميقة — الترتيب الداخلي تكرارًا = مكدس تدفع عليه اليساريَّات وتحذف بين حركات اليمين؛ الترتيب الأمامي = ادفع اليمين ثم اليسار. النسخة العودية هي مرساة الذاكرة؛ اشتق التكرارية منها تحت الضغط.

شجرة البحث الثنائية وحقيقة الشجرة المتوازنة

إدراج/بحث/حذف شجرة البحث الثنائية O(log n) حين تكون متوازنة. غير المتوازنة (مدخلات مرتبة، إدراج ساذج) تتدهور إلى O(n) — قائمة مترابطة متنكّرة. هذا هو السبب كله في وجود أشجار AVL/الحمراء-السوداء (توازن ذاتي عند كل إدراج). في المقابلات: اعرف أن أشجار البحث الثنائية المتوازنة تعطيك عمليات مرتبة بحدود O(log n) — وأن كود الإنتاج يستخدم هياكل مكتبة بدلًا منها: Map/Set في JS، أو مصفوفة مرتبة + بحث ثنائي، وهي O(n) في الإدراج لكنها O(log n) في البحث ومقبولة لـ n صغير.

تري — مطابقة البادئات

الـ trie شجرة من الأحرف: كل عقدة تحمل خريطة لأحرف الأبناء وعلم «كلمة تنتهي هنا». الإدراج والبحث O(طول الكلمة).

class Trie {
  constructor() { this.root = { children: {}, end: false }; }
  insert(word) {
    let node = this.root;
    for (const ch of word) {
      node.children[ch] ??= { children: {}, end: false };
      node = node.children[ch];
    }
    node.end = true;
  }
  search(word) {
    let node = this.root;
    for (const ch of word) {
      if (!node.children[ch]) return false;
      node = node.children[ch];
    }
    return node.end;
  }
}

متى يربح: الإكمال التلقائي (انزل إلى البادئة ثم عدّد الشجرة الفرعية)، والبحث عن كلمة على لوحة، واستعلامات «يبدأ بـ». البديل — خريطة تجزئة لكل بادئة — ينجح لكنه يهدر الذاكرة؛ الـ trie يشارك البادئات بنيويًا.

الكومة / قائمة الأولويات — نمط top-K

الكومة شجرة ثنائية بثابت واحد: الأب ≤ (كومة صغرى) أو ≥ (كومة كبرى) أبنائه. push وpop كلاهما O(log n)، وpeek O(1). يعطي ذلك مكسبين كلاسيكيين:

  • Top-K: «k أكبر/أصغر، k الأكثر تكرارًا، k الأقرب» — كومة صغرى بحجم k: ادفع كل عنصر؛ وحين تتجاوز الكومة k، احذف الأصغر. النتيجة: الـ k الأكبر في O(n log k) — لا فرز كامل مطلوب.
  • صيانة الوسيط: كومتان — كبرى للنصف الأدنى، وصغرى للنصف الأعلى، معادلة التوازن بعد كل إدراج. الوسيط = peek للكومة الأكبر (أو متوسط القمتين). O(log n) لكل إدراج.
  • دمج k قائمة مرتبة: ادفع رأس كل قائمة، واحذف الأصغر، وادفع خلفه — شكل «دمج k أشياء» القياسي.

لا كومة مدمجة في JS — حركة المقابلة هي تنفيذ كومة ثنائية صغيرة (~25 سطرًا: push/pop مع صعود-غربلة/نزول-غربلة) مرة واحدة من الذاكرة، أو استخدام Array.sort() حين يكون n صغيرًا بما يكفي (الفرز كثيرًا ما يكون الإجابة الصحيحة الأكسل).

class MinHeap {
  constructor() { this.a = []; }
  size() { return this.a.length; }
  peek() { return this.a[0]; }
  push(v) {
    this.a.push(v);
    let i = this.a.length - 1;
    while (i > 0) {                 // sift-up: swap with parent
      const p = (i - 1) >> 1;
      if (this.a[p] <= this.a[i]) break;
      [this.a[p], this.a[i]] = [this.a[i], this.a[p]];
      i = p;
    }
  }
  pop() {
    const top = this.a[0];
    const last = this.a.pop();
    if (this.a.length) {
      this.a[0] = last;
      let i = 0;
      while (true) {                // sift-down: swap with smaller child
        const l = 2 * i + 1, r = l + 1;
        let m = i;
        if (l < this.a.length && this.a[l] < this.a[m]) m = l;
        if (r < this.a.length && this.a[r] < this.a[m]) m = r;
        if (m === i) break;
        [this.a[m], this.a[i]] = [this.a[i], this.a[m]];
        i = m;
      }
    }
    return top;
  }
}

الثابتان اللذان يجب إبقاؤهما واضحين: صعود-غربلة عند push (العنصر الجديد يمشي نحو الجذر ما دام أصغر من أبيه)، ونزول-غربلة عند pop (العنصر الأخير المرقَّى يمشي نحو الأوراق ما دام أكبر من ابن). كومة كبرى: اقلب المقارنات. ولأجل «k الأكبر»، ادفع إلى كومة صغرى بحجم k — الجذر هو أصغر أعلى-k الحالي، فهو المرشَّح للإخراج.

العودية — الحركة ذاتية الإحالة

كل هيكل أعلاه محدود وملموس؛ العودية هي فكرة أن الدالة يمكن أن تكون قالبها الخاص — مسألة تُحل بحل نسخة أصغر من المسألة نفسها. أنت تستخدمها منذ اجتيازات الأشجار (§٤): inorder(node) تستدعي inorder(node.left). معالجة مستقلة لأنها المحرك خلف DFS (§٦)، والتقسيم والغزو (§٧)، والبرمجة الديناميكية (§٨)، ولأن نمطي الفشل شائعان ورخيصا الإصلاح.

الشكل، دائمًا جزءان: حالة أساسية توقف العودية (أصغر مدخل، لا استدعاء آخر)، وحالة عودية تستدعي نفسها على مدخل أصغر بدقة. إذا فشلت الحالة العودية في الانكماش نحو الحالة الأساسية، ستحصل على عودية لا نهائية → فيض المكدس. هذا هو الانضباط كله.

// power(x, n): multiply x by power(x, n-1) — smaller input, base case at n === 0
function power(x, n) {
  if (n === 0) return 1;              // base case
  return x * power(x, n - 1);         // recursive case, strictly smaller
}

كيف تكتب واحدة تحت الضغط: 1) حدّد أصغر مدخل واكتب إجابته كحالة أساسية؛ 2) ثِق بأن الاستدعاء العودي ينجح للمدخلات الأصغر («وثبة الإيمان» — لا تتعقّبه)؛ 3) اسأل: «بمعرفة إجابة حالة أصغر، كيف أبني إجابة هذه؟» الخطوة الأخيرة هي السؤال نفسه الذي تطرحه البرمجة الديناميكية — العودية مع كاش هي برمجة ديناميكية محفوظة (memoized)، لذا فالحل العودي النظيف يبعد مذكرةً واحدة عن حل برمجة ديناميكية (§٨).

متى تتخلى عن العودية: كل استدعاء يحرق إطار مكدس؛ السلاسل العميقة (شبكة من 10,000 خلية في DFS، قائمة طويلة جدًا) تُفيض مكدس الاستدعاءات — حد عودية، لا خطأ منطقي. مهران للنجاة: اجعلها تكرارية بمكدس صريح (تتحكم في الذاكرة)، أو استخدم BFS (§٦) الذي لا يتراجع أبدًا. أي شيء تكتبه عوديًا يمكنك كتابته بمكدس تدفع عليه — المكدس هو العودية. قاعدة عامة: العودية لأعماق الأشجار (آمنة، O(log n))؛ والمكدس الصريح لأعماق الرسوم البيانية (عشوائية).

BFS — القالب

// shortest path (unweighted) from start; dist of -1 = unreachable
function bfs(graph, start, n) {
  const dist = new Array(n).fill(-1);
  dist[start] = 0;
  const queue = [start];
  for (let qi = 0; qi < queue.length; qi++) {   // index pointer = O(1) shift
    const u = queue[qi];
    for (const v of graph[u] ?? []) {
      if (dist[v] === -1) { dist[v] = dist[u] + 1; queue.push(v); }
    }
  }
  return dist;
}

القواعد: الزيارة الأولى = أقصر مسافة (هذا ما يجعل BFS خوارزمية أقصر المسارات على الرسوم غير الموزونة)؛ علّم على الزيارة عند الإدراج في قائمة الانتظار (enqueue) لا عند الإخراج (dequeue)، وإلا أدخلت مكررات؛ قائمة الانتظار بمؤشر فهرس تتجنب shift() بـ O(n). «Rotting oranges» و«walls and gates» و«nearest 0» — كلها الشكل نفسه ببداية متعددة المصادر (أدرج كل المصادر أولًا).

DFS — عودي وتكراري

// connected components: every node gets its component id
function components(graph, n) {
  const comp = new Array(n).fill(-1);
  let id = 0;
  function dfs(u) {
    for (const v of graph[u] ?? []) if (comp[v] === -1) { comp[v] = id; dfs(v); }
  }
  for (let u = 0; u < n; u++) if (comp[u] === -1) { comp[u] = id; dfs(u); id++; }
  return comp;
}

متى يتفوق DFS على BFS: بلوغ الهدف (reachability)، وكشف الحلقات (موجّه: ثلاث حالات — غير مزار / قيد المعالجة / منجز — حافة إلى عقدة قيد المعالجة هي حافة رجعية)، والترتيب الطوبولوجي (أدناه)، وأي شيء عودي (إغراق الشبكة — «number of islands» هي هذه الحلقة مع dfs من نوع flood-fill). للشبكات العميقة، يمكن أن تفجّر العودية مكدس الاستدعاءات — النسخة التكرارية تستخدم مكدسًا صريحًا، ومجموعة مزارة عند الدفع.

الترتيب الطوبولوجي — DFS أو خوارزمية Kahn

ترتيب الاعتماديات: «أكمل كل المتطلبات الأساسية» أو «جدول المقررات». خوارزمية Kahn: عدّ درجات الدخول، وأدرج عُقد الدرجة صفر، وعالج، وأنقص الجيران؛ إذا كان العدّ المعالَج < V، فهناك حلقة. نسخة DFS تراكم بالترتيب اللاحق ثم تنعكس. كلاهما O(V + E) وكلاهما يعمل أيضًا ككاشف حلقات — إجابة «هل يمكن فعله أصلًا؟» التي تسألها المسألة فعلًا.

Dijkstra — أقصر مسار موزون

ابن عم BFS الموزون: فكرة «أول تسوية = الأفضل» نفسها، لكن قائمة الانتظار تصبح قائمة أولويات مفتاحية بـالمسافة، وتتخطى الإدخالات البالية:

function dijkstra(graph, start, n) {
  const dist = new Array(n).fill(Infinity); dist[start] = 0;
  const pq = [[0, start]]; // binary heap of [dist, node]
  while (pq.length) {
    const [d, u] = heapPop(pq);
    if (d > dist[u]) continue;            // stale entry — skip
    for (const [v, w] of graph[u] ?? []) {
      if (d + w < dist[v]) { dist[v] = d + w; heapPush(pq, [dist[v], v]); }
    }
  }
  return dist;
}

القاعدة المهمة: Dijkstra يفشل مع الحواف السالبة (عقدة مُسوّاة بالفعل يمكن تحسينها لاحقًا) — هذه مهمة Bellman-Ford. و«أقصر مسار في شبكة» هو BFS فقط حين تكلف كل الحركات نفس الشيء؛ شبكة 0/1 يمكنها استخدام deque (حركات التكلفة صفر تُدفع للأمام).

اتحاد-بحث — ترابط دون بناء الرسم البياني

class UnionFind {
  constructor(n) { this.parent = Array.from({length: n}, (_, i) => i); this.rank = new Array(n).fill(0); }
  find(x) { while (this.parent[x] !== x) { this.parent[x] = this.parent[this.parent[x]]; x = this.parent[x]; } return x; }
  union(a, b) {
    const ra = this.find(a), rb = this.find(b);
    if (ra === rb) return;
    if (this.rank[ra] < this.rank[rb]) [ra, rb] = [rb, ra];
    this.parent[rb] = ra;
    if (this.rank[ra] === this.rank[rb]) this.rank[ra]++;
  }
}

لماذا هو الرابح الخفي: «عدد المكونات المترابطة في شبكة»، و«دوائر الأصدقاء»، و«دمج الحسابات»، وKruskal MST — أي شيء عن الترابط ينمو حافةً حافة. ضغط المسارات (حلقة find التي تختصر الطريق إلى الجذر) + اتحاد بالرتبة يجعلان العمليتين شبه O(1) مطفأ — أسرع من إعادة تشغيل BFS بعد كل حافة جديدة.

البحث الثنائي — القالب الذي لا يخطئ بواحد

// first index where isGood(i) is true, else hi+1... pattern:
let lo = 0, hi = arr.length;          // search space [lo, hi)
while (lo < hi) {
  const mid = (lo + hi) >> 1;         // floor, no overflow in JS
  if (isGood(mid)) hi = mid;          // good → keep mid
  else lo = mid + 1;                  // bad → discard mid
}
return lo;                            // first good index
  • الثابت: النطاق [lo, hi) نصف المفتوح، «أول فهرس يقلب فيه المسند من خطأ إلى صواب». بحث عن قيمة: isGood = arr[mid] >= target — الإجابة هي أول عنصر ≥ target (وهذا يعالج «الهدف موجود» و«موضع الإدراج» في واحد).
  • الاشتقاقات (أول/آخر ظهور، السقف، نقطة الدوران) كلها تختزل إلى اختيار المسند — لا تعِد كتابة جسم الحلقة أبدًا، غيّر isGood فقط.
  • النمط الخفي: البحث الثنائي ينجح مع أي مسند رتيب، لا المصفوفات المرتبة فقط — «أصغر سعة يمكنها الشحن في d أيام»، «أصغر مسافة زوجية في المرتبة k» — إذا كان فضاء الإجابات رتيبًا (هل أستطيع تحمل X؟ نعم ← نعم أيضًا لـ X أكبر)، ابحث عن الإجابة ثنائيًا.

البرمجة الديناميكية — آلة حالة التحسين

البرمجة الديناميكية أصعب العائلات لأنها تبدو كالعودية وهي في الحقيقة تعداد محفوظ (cached enumeration). الإطار، مطبَّق في كل مرة:

  1. حدّد الحالة — وصف الحد الأدنى لمسألة فرعية: «dp[i] = أقصى ربح مع i عنصرًا»، «dp[r][c] = المسارات إلى الخلية (r, c)». الحالة أهم قرار منفرد؛ حالة خاطئة تعني إجابة خاطئة تبدو صحيحة.
  2. اكتب الانتقال — كيف تُبنى dp[i] من حالات أصغر: «dp[i] = max(dp[i-1], dp[i-2] + v[i])». إن لم تستطع كتابة الانتقال، فأنت لم تفهم التكرار بعد — عُد إلى تعريف الحالة.
  3. ضيِّع الحالات الأساسية — dp[0]، dp[1]، صف/عمود الشبكة الفارغ. الحالات الأساسية حيث يموت معظم أخطاء الإزاحة بواحد (off-by-one).
  4. اختر الحفظ أو الجدولة — memo = عودية + كاش (اكتب عودية القوة الغاشمة، أضف الكاش، انتهيت — أنظف طريق صحيح)؛ tabulation = ابنِ الجدول من الأسفل لأعلى، ويتجنب العودية وكثيرًا ما يحتاج مساحة أقل.

الترتيب الكسول تحت ضغط الوقت: 1) عودية القوة الغاشمة (صحيحة، بطيئة)، 2) أضف كاش memo (الآن O(n · حالات))، 3) إذا كانت الذاكرة هي القيد، حوّل إلى جدولة واضغط الجدول (أبقِ الصف/العمود الأخير فقط — معظم البرمجيات الديناميكية 1D و2D تحتاج صفًا أو صفين فقط). الخطوتان 1–2 غالبًا تكفيان للنجاح.

ملاحظة وظيفية (الحد الفاصل FP): البرمجة الديناميكية المحفوظة دوال نقية + كاش — فكرة «تذكّر الإجابة» نفسها التي يحصل عليها حساب اللامدا بالاستبدال. reduce هي حلقة الجدولة متنكّرة: states.reduce((acc, x) => transition(acc, x), base) هي برمجة ديناميكية 1D بمجمّع واحد. أسس FP على الرف (What Is State، وJavaScript: The Language) هي كل ما تحتاجه من FP هنا — لا حاجة إلى monads.

الجشع — الكذبة الجميلة

الجشع: خذ الحركة الأفضل محليًا وارجُ أن تكون مثالية عالميًا. حين ينجح يكون O(n) وأنيقًا؛ وحين لا ينجح يكون خاطئًا بإجابة تبدو معقولة. الاختبار هو حجة التبادل: «إذا اختلف حل مثالي عن حلّي، يمكنني مبادلة اختياري مكانه دون جعله أسوأ» — إن لم تستطع رسم تلك الحجة، فالجشع مقامرة، والبرمجة الديناميكية هي الإجابة الآمنة.

  • جدولة الفترات — «أقصى اجتماعات غير متداخلة»: رتّب بوقت النهاية، وخذ دائمًا أول ما ينتهي والمتوافق. الجشع النموذجي وحجة التبادل التي يتعلمها الجميع أولًا.
  • اختيار الأنشطة / القفزات — «jump game»: عند كل موضع، تذكّر أبعد مدى؛ الجشع ينجح لأن المجموعة القابلة للوصول تنمو فقط.
  • ترميز هوفمان — ادمج دائمًا الأصغرين؛ تخرج رموز البادئة المثلى من تلقاء نفسها.
  • العلامة المميزة: مسائل مصاغة «قلّل عدد X» أو «عظّم Y بهذه الموارد» حيث توجد حجة ترتيب بسيطة. عند الشك، برمجة ديناميكية.

التلاعب بالبتات والرياضيات — درج الحِيَل

  • خصائص XOR: a ^ a = 0، وa ^ 0 = a، وXOR إبدالية/تجميعية → «العدد الوحيد الذي يظهر مرة واحدة بين أزواج» هو arr.reduce((a, b) => a ^ b). XOR أيضًا يبادل متغيرين ويجد العددين الفريدين (اجمع الكل بـ XOR، ثم انشق على بت مضبوط).
  • حِيَل البتات: n & (n - 1) يمسح أدنى بت مضبوط (→ عدّ البتات بحلقته)، n & -n يعزل أدنى بت مضبوط (→ خدعة الانشقاق أعلاه)، x >> 1 قسمة على 2 (منتصف البحث الثنائي).
  • الأقنعة: قناع البتات مجموعة أعداد صحيحة صغيرة — «المجموعات الفرعية لعناصر n» = تكرر 0..2ⁿ-1 واختبر mask & (1 << i). فقط لـ n ≤ 20.
  • أساسيات الرياضيات: القاسم المشترك الأكبر عبر إقليدس (while (b) [a, b] = [b, a % b])، والحساب النمطي (قواعد a mod m؛ الرفع النمطي بالتربيع المتكرر)، ومنخل إراتوستينس للأعداد الأولية حتى n في O(n log log n)، والتوافقيات (n اختر k عبر مثلث باسكال / الصيغة الضربية).

ورقة تذكّر التعرف على الأنماط — الإشارة ← التقنية

الرفيق لجداول التعرف في Problem-Solving §7b — النسخة التشغيلية، الإشارة أولًا:

إذا قالت المسألة…مدّ يدك إلى…لماذا
«count / seen before / unique / complement» — عدّ / رأيتُ من قبل / فريد / مكمّلخريطة تجزئة أو مجموعةعضوية O(1) — الخطوة الأولى الافتراضية
«sorted + pair/triplet sum / palindrome in place» — مرتب + مجموع زوج/ثلاثي / متناظر في المكانالمؤشرانO(n) على مدخلات مرتبة؛ كل مؤشر يتحرك مرة واحدة
«longest / contiguous / subarray / substring» — الأطول / المتصل / مصفوفة فرعية / سلسلة فرعيةالنافذة المنزلقةقيد النافذة المتصلة، O(n) مطفأ
«k largest / k most frequent / median of stream» — الـ k الأكبر / الـ k الأكثر تكرارًا / وسيط دفقكومة (top-K، كومتان)O(log k) لكل عنصر، بلا فرز كامل
«matching / parentheses / undo / next greater» — مطابقة / أقواس / تراجع / التالي الأكبرمكدس (رتيب)بنية LIFO تطابق التداخل
«shortest path / levels / nearest» (غير موزون) — أقصر مسار / مستويات / الأقربBFSالزيارة الأولى = أقصر مسافة
«reachable / cycles / components / flood fill» — قابل للبلوغ / حلقات / مكونات / تعبئة فيضانDFSيستكشف كل شيء؛ خدعة الحالات الثلاث تجد الحلقات
«shortest path» (موزون)، «cheapest flight» — أقصر مسار / أرخص رحلةDijkstraقائمة أولويات بالمسافة، تسوية-مرة
«connected components growing / edges added one by one» — مكونات مترابطة تنمو / حواف تُضاف واحدة واحدةاتحاد-بحثشبه O(1) لكل اتحاد — يتفوق على إعادة تشغيل BFS
«prerequisites / ordering / dependencies» — متطلبات أساسية / ترتيب / اعتمادياتترتيب طوبولوجيKahn أو ترتيب لاحق DFS؛ يعمل أيضًا ككشف حلقات
«sorted / find insert position / monotonic answer» — مرتب / إيجاد موضع إدراج / إجابة رتيبةبحث ثنائيأيضًا لمسائل «قلّل الأقصى X» ذات المسند الرتيب
«minimize cost / maximize value / choose subsets» — قلّل الكلفة / عظّم القيمة / اختر مجموعات فرعيةبرمجة ديناميكية أو جشعجشع إذا صمدت حجة التبادل، وإلا برمجة ديناميكية — حالات، انتقال، أساس
«prefix / words sharing prefixes / autocomplete» — بادئة / كلمات تتشارك بادئات / إكمال تلقائيتريالمشاركة البنيوية تتفوق على تخزين كل بادئة
«appears once / bit tricks / subsets of small n» — يظهر مرة واحدة / حِيَل بتات / مجموعات فرعية لـ n صغيرتلاعب بالبتاتمطابقات XOR؛ أقنعة لـ n ≤ 20
«range sum / range queries, point updates» — مجموع نطاق / استعلامات نطاق وتحديثات نقطيةمجاميع بادئة، ثم شجرة قطع/فينويك للتحديثاتالبادئة = استعلامات O(1)؛ فينويك = تحديثات O(log n)

تذكير بترتيب القراءة: لا تبدأ البرمجة قبل التصنيف أبدًا. إذا لم تناسب المسألة أي صف، فالقوة الغاشمة تصنيف شرعي — نفّذها، ثم ابحث عن ترقية «ما الذي يمكنني تذكّره؟» (قاعدة المرحلة 3 في Problem-Solving).

الخلاصة — قائمة الفحص الذهنية الكاملة

الوثيقة في اثني عشر سطرًا:

#السطر
1المصفوفات وخرائط التجزئة والأشجار هي 80% من الكود الحقيقي — أتقن §٢ وردّ فعل «ما الذي يمكنني تذكّره؟».
2O(1) لخريطة التجزئة يعتمد على معامل التحميل؛ استخدم Map/Set، لا كائنًا عاديًا أبدًا (§٢).
3المؤشران والنافذة المنزلقة والمجاميع البادئة: الحركات المصفوفية الثلاث التي تجعل «الأطول / الزوج / النطاق» خطية (§٢).
4المكدس الرتيب = «التالي الأكبر» في O(n)؛ خدعة الرأس الوهمي تقتل فئة كاملة من أخطاء القوائم (§٣).
5الاجتيازات أولًا؛ BFS = أقصر مسار على الرسوم غير الموزونة، وDFS بثلاث حالات = كشف الحلقات (§٤، §٦).
6اتحاد-بحث للترابط، وترتيب طوبولوجي للترتيب، وDijkstra لأقصر مسار موزون (§٦).
7البحث الثنائي محرك مسند رتيب، لا خدعة مصفوفة مرتبة — نطاق نصف مفتوح، فهرس أول-جيد (§٧).
8الفرز معالجة مسبقة: «k الأصغر» و«دمج الفترات» و«مجموعات anagram» كلها تصبح خطية بعد فرز واحد (§٧).
9البرمجة الديناميكية = تعداد محفوظ: حالة، انتقال، أساس — ثم احفظ قبل أن تجدول (§٨).
10الجشع بلا حجة تبادل مقامرة؛ عند الشك، برمجة ديناميكية (§٩).
11صنّف قبل البرمجة — ورقة الغش ترسم الإشارة إلى التقنية؛ القوة الغاشمة تصنيف احتياطي صالح (§١١).
12شغّل جدول أنماط الفشل بعد كل حل: حافات بحجم ≤ 2، مدخلات كلها سالبة، فيض، تعديل أثناء التكرار (§١٣).
