HTML و CSS — طبقة المنصة بين المتصفح والمكون

العقد الذي ينفذه المتصفح: بنية المستند، التدرج، التخطيط، السمات، وشجرة إمكانية الوصول. وثائق شقيقة: تصميم UI/UX والويب (انضباط العرض الذي يعيش داخل هذه الركيزة)، كيف يفكر المطورون (حلقة التنفيذ التي تستهلك هذه العناصر الأولية)، JavaScript: اللغة (اللغة التي تتلاعب بهذه الركيزة)، التصميم المعماري (الطبقة المعمارية التي تعمل استراتيجية عرضها على هذه المنصة)، مسح معسكرات الواجهات الأمامية (خيارات الأطر تستخلص هذه الطبقة بشكل مختلف).

٠. كيف تستخدم هذا المستند

ترتيب القراءة: مستقل. روابط تقاطعية:

  • أعلى إلى تصميم UI/UX والويب — UI/UX يقرر ما يجب أن يكون الشيء المعروض؛ HTML و CSS هي الركيزة التي يعرض عليها. مصفوفة رؤية الحالة (§9 في UI/UX) تُرسم مباشرة إلى حالات HTML (aria-busy، aria-invalid) وحالات CSS (:hover، :focus-visible، [data-loading]).
  • أسفل إلى كيف يفكر المطورون عند بناء ميزة واجهة أمامية — حلقة المطور تبني المكونات باستخدام عناصر HTML وقواعد CSS كعناصر أولية. قرارات الحلقة "الشكل" (API المكون، شكل الحالة) مقيدة بما تجعل المنصة قابلاً للتعبير.
  • تقاطعي مع JavaScript: اللغة — JS تتلاعب بـ DOM (شجرة HTML في الذاكرة) و CSSOM (ورقة أنماط CSS في الذاكرة). هذا المستند يشرح ما هاتان الشجرتان وكيف يحل التدرج قبل أن تلمسها JS.
  • تقاطعي مع التصميم المعماري — استراتيجية العرض (SSR، RSC، Islands، SPA) هي قرار حول من يصدر HTML الأولي ومتى يصل CSS. عقد المنصة (تحليل HTML، حظر CSS، تحميل الخطوط) هو الحقيقة الأساسية التي تفاوض كل استراتيجية معها.
  • سياق من مسح معسكرات الواجهات الأمامية — كل معسكر (React، Vue، Svelte، Solid، Qwik، Astro) هو استخلاص مختلف فوق نفس الركيزة. الركيزة لا تتغير؛ تسرب الاستخلاص هو ما يختلف.
  • مرجع: المصطلحات — مفردات مشتركة عبر جميع وثائق المراجع.

إجابة الشجرتين لـ "ما هي منصة الويب؟"

  • DOM (نموذج كائن المستند) — شجرة HTML المحللة. عناصر، سمات، عقد نصية. البنية التي يعرضها المتصفح لـ JavaScript. document.querySelector('article') يعيد عقدة DOM.
  • AOM (نموذج كائن إمكانية الوصول) / شجرة إمكانية الوصول — شجرة موازية مشتقة من DOM، مفلترة للدوال.

CSS تعمل على بنية ثالثة: شجرة العرض (DOM + قيم محسوبة → صناديق). التدرج، التخطيط، الرسم، والتركيب يحدثون هنا. ثلاث شجرات، مصدر واحد: HTML الذي تكتبه.

١. تعريف — ما هو HTML و CSS وما ليس به

ما هو

HTML و CSS هو عقد عرض تصريحي، متدرج، قابل للوصول افتراضياً لمنصة الويب. ينتج قرارات — لا تعليمات إجرائية — تحدد:

  • بنية المستند ودلالاته — ما العناصر الموجودة، كيف تتداخل، ما تعني (
    مقابل
    مقابل
    ). DOM هو نتيجة التحليل؛ AOM هو الإسقاط الدلالي.
  • خوارزمية التدرج — كيف تتنافس الإعلانات: المصدر (وكيل المستخدم / المستخدم / المؤلف)، الأهمية (!important)، التحديدية، ترتيب المصدر، قرب النطاق، طبقات التدرج. حتمية، قابلة للفحص، غير إجرائية.
  • نموذج الصندوق وسياقات التنسيق — كل عنصر يولد صناديق (محتوى، حشو، حد، هامش). الصناديق تشارك في سياقات تنسيق (التدفق العادي، flex، grid، table، ruby). التخطيط هو حل قيود على الصناديق.
  • التنسيق البصري والسمات — اللون، الطباعة، المسافات، الحركة، الظلال، الحدود، المرشحات، أوضاع المزج. معبرة كقيم محسوبة على الصناديق.
  • كشف الحالة — فئات مزيفة (:hover، :focus-visible، :disabled، :valid، :placeholder-shown)، محددات السمات ([aria-busy="true"]، [data-state="loading"])، استعلامات الحاوية (@container). المنصة تكشف الحالة؛ CSS تختارها.
  • التجاوب والتحجيم الجوهري — استعلامات الوسائط (@media)، استعلامات الحاوية (@container)، min()/max()/clamp()، fit-content، min-content، max-content. التخطيط يتكيف مع القيود بدون JS.
  • إمكانية الوصول كافتراض — HTML الدلالي هو API إمكانية الوصول. ،
    /، aria-* فقط عند وجود فجوة دلالية. خط أساس WCAG 2.2 AA.

هذه القرارات مكلفة للتغيير لاحقاً. إعادة هيكلة CSS تمس كل مكون. تدقيق دلالات HTML يمس كل قالب. كلما دخلت قرارات المنصة أبكر، كان النظام أرخص.

٤. تقاطع مع الجيران — حيث تحد ممارسات أخرى

الممارسةDNA مشتركأين تختلف
تصميم UI/UX والويب رؤية الحالة، إمكانيات الفعل، إمكانية الوصول، التسلسل الهرمي البصري، الحركة، الرموز UI/UX يقرر ما يختبره الإنسان؛ HTML و CSS هي الركيزة التي تجعله ممكناً. UI/UX تصمم مصفوفة الحالة؛ HTML/CSS تنفذ خطافات aria-busy/[data-state] والفئات المزيفة التي تكشفها.
حلقة المطور (الواجهة الأمامية) شكل المكون، الخصائص، الحالة، العرض، الأداء، الترطيب الحلقة تكتب مكونات تصدر HTML و CSS؛ المنصة تحلل، تتدرج، تخطّط، ترسم. قرارات الحلقة "الشكل" (ما الخصائص، ما الحالات) مقيدة بما توجد عناصر HTML وما يمكن CSS اختياره.
JavaScript: اللغة DOM API، CSSOM، حلقة الأحداث، microtaps، مراقبات التحور JS تتلاعب بالأشجار (DOM، CSSOM، AOM)؛ HTML و CSS تعرف البنية الأولية للأشجار وخوارزمية التدرج. JS لا تستطيع إصلاح تدرج مكسور؛ فقط تتحور بعد الحقيقة.
التصميم المعماري استراتيجية العرض (SSR/RSC/Islands)، CSS الحرج، تحميل الخطوط، الترطيب، التدفق التصميم المعماري يقرر متى وأين يصدر HTML/CSS؛ المنصة تعرف ما يعني "إصدار" (حظر المحلل، حظر العرض، تنازل المحلل). أولية منصة؛ التصميم المعماري يقرر أي أوراق تحصل عليها.
مسح معسكرات الواجهات الأمامية React (JSX → HTML)، Vue (SFC → HTML)، Svelte (تجميع → HTML+CSS)، Astro (jزر → HTML) كل معسكر استخلاص فوق الركيزة. React الركيزة. الركيزة (تحليل HTML، تدرج CSS، تخطيط) متطابقة؛ تسرب الاستخلاص (الترطيب، تحديد نطاق الأنماط، التسلسل) يختلف.
إمكانية الوصول (WCAG / ARIA) HTML دلالي، aria-*، إدارة التركيز، التباين، حركة مخفضة WCAG هو خط أساس الامتثال؛ HTML و CSS هي المنصة التي تجعل الامتثال افتراضياً.
أنظمة التصميم / رموز التصميم لون، مسافات، طباعة، حركة، حد، ظل كبيانات منظمة الرموز (صيغة W3C DTCG) تترجم إلى خصائص CSS المخصصة. المنصة هي وقت تشغيل الرموز: التوريث، البديل، كتابة @property، calc() مع متغيرات. أنظمة التصميم تؤلف الرموز؛ المنصة تحلها.
الأداء / Core Web Vitals CLS، LCP، INP، TTFB، حظر العرض، تحميل الخطوط الأداء يقيس سلوك المنصة؛ HTML و CSS هو السلوك المقاس. ، font-display، content-visibility، will-change أزرار منصة. المنصة لا تحسّن؛ أنت تفعل.

٦. الإيقاع، لا الخوارزمية

مثل تصميم UI/UX والويب، التصميم المعماري، و تصميم API، HTML و CSS هو إيقاع، لا خوارزمية منظمة. يفشل اختبارات الخوارزمية الثلاثة:

  • المدخلات غير معرفة مسبقاً. لا تعرف كل المحتوى المستقبلي، أحجام المنافذ، تفضيلات المستخدم (وضع داكن، حركة مخفضة، تباين عالي)، أو قدرات المتصفح عند كتابة أول قاعدة. المنصة تكتشفها وقت التشغيل.
  • الخطوات غير حتمية. لا توجد قاعدة تقول "الآن التقط Grid". تختار Grid عندما يتطلب التصميم محاذاة ثنائية البعد بمسارات جوهرية — قرار حكم. @container مقابل @media قرار سياق، لا حكم.
  • لا إنهاء ثابت. "منجز" يعني "المكون يعرض بشكل صحيح عبر مصفوفة الدعم (متصفحات، منافذ، أوضاع، شجرة a11y) والتدرج قابل للفحص بلا !important." ذلك قرار، لا حكم. المنصة تتطور؛ المكون يتكرر.

هذا لماذا يقاوم HTML و CSS قوائم تحقق تتظاهر بالكمال. قائمة تحقق تفترض أنك تعرف المحتوى والسياق النهائيان؛ الإيقاع يفترض أنك تعرف ما ينقص للسياق الذي لديك — قرار منصة/هندسة.

اختراق الإيقاع "رموز التصميم → خصائص CSS المخصصة". رموز التصميم (صيغة W3C DTCG) تترجم إلى خصائص CSS المخصصة. تدرج المنصة + التوريث + البديل + كتابة @property هو وقت تشغيل الرموز. تغيير رمز = تغيير متغير CSS واحد = انتشار فوري لكل مكون. لا خطوة بناء، لا إعادة نشر. مضاعف سرعة — مفيد حين يكون نظام الرموز حياً، خطير حين تصبح الرموز بيروقراطية تمنع الانحراف لكل مكون.

٨. المبادئ — الثوابت المشتركة

عبر كل منهجية، ثماني مبادئ تصمد (مستخلصة من مواصفات HTML/CSS، WCAG، وثوابت المنصة):

  1. HTML الدلالي هو API إمكانية الوصول.
  2. التدرج سياسة عامة، لا ذوق شخصي. أوراق أنماط المستخدم تفوز. !important في CSS المؤلف انتهاك سياسة — يمنع وكالة المستخدم (تباين عالي، خطوط مخصصة، تكبير). استخدم طبقات التدرج، التحديدية، وترتيب المصدر بدلاً منه.
  3. اختيار نظام التخطيط لا رجعة فيه تقريباً لكل جذر سياق تنسيق. أبناء حاوية flex هم عناصر flex. أبناء حاوية grid هم عناصر grid. لا يمكنك مزج سياقات تنسيق على نفس الأبناء. اختر في الحاوية؛ الأبناء يطيعون.
  4. التحسين التدريجي عقد، لا اقتراح. HTML يعمل بلا CSS. CSS يعمل بلا JS. JS يعزز، لا يحجب. المنصة تضمن هذا إن لم تكسره (مثلاً
  5. رموز على أرقام سحرية. padding: var(--space-4) لا padding: 16px. color: var(--color-primary) لا color: #3b82f6. الرموز تمكّن وضع داكن، كثافة، سمات، ومزامنة عبر منصات. أرقام سحرية تضمن الانحراف.
  6. الأداء ميزة منصة تهيئها. ، font-display: swap، content-visibility: auto، will-change (باقتراح). المنصة لا تحسّن لك؛ تكشف أزرار. قس (CLS، LCP، INP)، ثم در الأزرار.
  7. الحالة تعيش في السمات، تُختار في CSS. [aria-busy="true"]، [data-state="loading"]، :disabled، :focus-visible. JS تبدل السمات؛ CSS تختار الحالات. لا JS-in-CSS (لا style="..." من JS)، لا CSS-in-JS منطق حالة.
  8. احترم تفضيلات المستخدم افتراضياً. @media (prefers-reduced-motion: reduce) يعطل حركة غير أساسية. @media (prefers-contrast: more) يعزز تباين. @media (prefers-color-scheme: dark) يبدل رموز. المنصة تكشف تفضيلات؛ أنت تحترمها.

البطاقة تتكيف مع عرضها الخاص لا المنفذ. في شريط جانبي (ضيق) تتراص؛ في الرئيسي (واسع) أفقية. لا استعلام وسائط مطلوب.

خطوة ٤ — وضع داكن، RTL، حركة مخفضة: صفر CSS إضافي

  • وضع داكن — الرموز تتبدل عبر @media (prefers-color-scheme: dark). OKLCH تحفظ الإضاءة الإدراكية؛ لا ألوان علامة تجارية "مهتزة".
  • RTL — الخصائص المنطقية (margin-inline-start، padding-inline-end، border-inline-start) تنعكس تلقائياً. Flex/Grid تحترم dir="rtl" على . الشارة تبقى في المقدمة؛ أفعال التذييل تنعكس.
  • حركة مخفضة — @media (prefers-reduced-motion: reduce) تصفر رموز الحركة. الانتقالات تصبح فورية. لا محفزات دهليزية.
  • تباين عالي / forced colors — @media (forced-colors: active) يعطل خلفيات/ظلال؛ ألوان النظام تتولى. border: 1px solid CanvasText يضمن رؤية.
