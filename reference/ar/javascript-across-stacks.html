مرجع · JS عبر المنصات

جافاسكريبت عبر المنصات: أين تعمل JS، ومن يحاربها

كيف تبدو JS من منظور الواجهة الأمامية، الخلفية، الجوّال، المدمج، والذكاء الاصطناعي — ما يستخدمه كل واحد من JS، ما لا يناسب JS، واللغات التي كتبت لملء تلك الفجوة (TypeScript، .NET/C#، Java/Spring Boot، Kotlin، Dart، Rust، Python). لكل منافس: جدول تموضع بفقرة واحدة عن النظرية التي تبرر إنشاء لغة جديدة بدلاً من تمديد لغة موجودة. وثيقة شقيقة لـ javascript-the-language.

لماذا توجد هذه الوثيقة

JS-اللغة شيء. JS-كما-تُنشر خمسة قصص مختلفة. حيث تعمل JS يغير ما تستخدمه منها، ما تتمنى لو اختلف، ومن بُني ليحل محلها. هذه الوثيقة تجيب: "إذا كانت JS في كل مكان، لماذا لا تزال هناك خمس لغات رئيسية أخرى في الصناعة؟" شقيقة لـ javascript-the-language و frontend-camps-survey — مسح المعسكرات يغطي معسكرات الواجهة الأمامية فقط؛ هذه تغطي منافسة مستوى اللغة عبر كل المنصات.

٠. كيف تستخدم هذه الوثيقة

ترتيب القراءة. ما يعنيه "منظور" هنا: نفس اللغة، مضيف مختلف + قيود مختلفة = مجموعة منافسين مختلفة.

مرجع: المصطلحات — مفردات مشتركة عبر جميع وثائق المراجع.

النمط. عبر كل المنظورات، تظهر قاعدة واحدة من البيانات: لغة جديدة تربح عندما يتغير القيد المهيمن ويراهن تصميم اللغة القديمة ضد القيد الجديد. JS ربحت المتصفح لأن القيد كان حجم التحميل 1995 + غراء برمجة نصية. TypeScript ربحت أدوات JS لأن القيد تغير لصيانة الفرق الكبيرة. Go ربحت الخدمات الشبكية لأن القيد تغير للتزامن أولاً. Rust ربحت الأنظمة لأن القيد تغير لأمان الذاكرة بدون GC. Java مدت بناء جملة C++ لكن ربحت على رهان JVM (اكتب مرة، شغّل في أي مكان). القاعدة: مدد عندما القيد غير متغير، اخترع عندما ينقلب.

١. منظور الواجهة الأمامية

ما تستخدمه الواجهة الأمامية من JS: اللغة + DOM + fetch + Canvas/WebGL + تفاعل WASM. ما JS-اللغة لا تستطيع فعله على الواجهة الأمامية: الحساب الثقيل، الخيوط، قواعد كود كبيرة آمنة النوعياً. Recap الـ ٥ معسكرات أمامية (رابط لـ camps-survey). لا منافس حقيقي على مستوى اللغة في الواجهة الأمامية (المتصفح يشغل JS + WASM فقط)؛ المنافسون هم أوقات تشغيل بديلة (WASM) ولغات تُترجم لـ JS (TS، PureScript، Elm، ReasonML).

٢. تحول TypeScript (المنافس الذي نجا)

TS ليس منظوراً منفصلاً — هو التطور الداخلي للمنظور الأمامي. لكنه يستحق قسمه الخاص لأنه المنافس الوحيد الذي لم يحارب JS من الخارج؛ بل استبدلها من الداخل. النظرية: تمديد JS بالأنواع التدريجية، لا كتابة لغة جديدة. لماذا فاز TS حيث خسر Dart و CoffeeScript (لا خطوة تجميع منفصلة وقت التشغيل، لا بناء جملة منفصل للكود القيمي، فقط أنواع). إصدار ٢٠١٢، رهان Angular 2 (٢٠١٤)، دعم Babel 7 + TS (٢٠١٨)، نقطة تحول ٢٠٢٠ "TS كافتراضي". جدول تموضع: TS مقابل JS — ما يحسّن كل منهما. قاعدة "TS تتبخر عند التجميع" — وقت التشغيل، JS هو ما يعمل.

٣. منظور الخلفية

ما تستخدمه الخلفية من JS: Node.js — حلقة الأحداث + npm + fs/net/http الوحدات. أحادية المسار، I/O غير حاصر، عملية واحدة تتعامل مع آلاف الاتصالات. نفس الحلقة من المتصفح، مزروعة في الخادم.

ما لا يناسب: العمل المكثف CPU (يسد الحلقة)، خيوط حقيقية (خيوط عاملة موجودة لكن ثقيلة)، صندوق حماية ذاكرة (عزلات V8 ليست JVM-grade)، عقود من أدوات الخلفية المؤسسية (JMX، JPA، Spring، تشخيصات .NET)، تجمع المواهب الذي يعرف Java/C# من الجامعة.

منافسون — جدول تموضع واحد لكل مسار:

٣.١ Java / Spring Boot

البعدNode.jsJava + Spring Boot
ما تحسّنهI/O-bound microservices، بدء سريع، وحدة مكدس JSنضج JVM، أدوات المؤسسات، "أعد كتابة الشركة في ٦ أشهر"
نموذج التزامنحلقة أحداثخيوط (Virtual threads في Java 21+)

النظرية—لم تمدد Java لغة C++ — بل راهنت على JVM (اكتب مرة، شغّل في أي مكان). القيود: تطبيقات المؤسسات تحتاج وقت تشغيل مُدار، أمان، نظام بيئي. JVM قدم ذلك؛ اللغة تتبع المنصة.

٣.٢ C# / .NET

البعدNode.jsC# + .NET
ما تحسّنهفرق JS، نظام بيئي واحدالافتراضي لمتاجر Microsoft، عمق BCL، أداء .NET 8+
التزامنحلقة أحداثasync/await + خيوط، Task Parallel Library
متى تفوزفرق JS، شركات ناشئة، Edgeفرق .NET، Azure، أداء عالي، نقل إرث
النظرية—C# لم تمدد Java — بل استبدلتها على CLR برهان أفضل على الأنواع، LINQ، async، pattern matching. Anders Hejlsberg مجدداً. القيد كان "مطورو المؤسسات على Windows يحتاجون لغة مُدارة". .NET Core (٢٠١٦) قلب قيد المنصة: الآن Linux/macOS أيضاً. اللغة لم تتغير؛ رهان المنصة فعل.

٣.٣ Go

البعدNode.jsGo
ما تحسّنهفرق JS، نظام بيئي واحدالتزامن أولاً، ثنائي ملف واحد، نشر بسيط
التزامنحلقة أحداث (خيط واحد)Goroutines + قنوات (CSP)
متى تفوزطبقة API، واجهات BFFخدمات ميكرو، CLI، Kubernetes، أدوات سحابية أصلية
النظرية—Go لم تمدد C++ — بل استبدلتها للخدمات الشبكية. القيود تغيرت: من "تحكم عاري" إلى "التزامن على نطاق Google". Goroutines تحل مشكلة C10k التي حلقة الأحداث تحلها بشكل مختلف. رأي في الأدوات (go fmt، go test، go mod) يمنع جدل التنسيق.

٣.٤ Rust

البعدNode.jsRust
ما تحسّنهسرعة التطوير، npmأمان ذاكرة بدون GC، طبقة أنظمة، أداء قابل للتنبؤ
التزامنحلقة أحداثasync/.await + tokio، تزامن بلا خوف (ملكية)
متى تفوزمعظم خدمات الويبمحركات، قواعد بيانات، WASM، بنية تحتية، حيث يهم كل ns/byte
النظرية—Rust لم تمدد C++ — بل قلبت رهانها: C++ قالت "لا GC للأداء"؛ Rust قالت "لا GC و لا أخطاء ذاكرة". مدقق الاستعارة (borrow checker) هو الرهان التصميمي الجديد. هذا انعكاس لغة الأنظمة: الأمان كضمان وقت تجميع، لا تكلفة وقت تشغيل.

٣.٥ Python

البعدNode.jsPython
ما تحسّنهI/O-bound، وحدة مكدس JSعلم البيانات، ML/AI، خطوط أنابيب البيانات، البرمجة الاستكشافية
نموذج التزامنحلقة أحداثGIL (CPU أحادي المسار)، multiprocessing، asyncio (حديث)
نظام الأنواعاختياري (TS)اختياري (type hints، mypy)، ديناميكي وقت التشغيل
عمق النظام البيئيnpmPyPI — NumPy، Pandas، PyTorch، TensorFlow، JAX، scikit-learn
متى تفوزطبقات API، خوادم ويبتدريب النماذج، خطوط أنابيب البيانات، البحث، الحوسبة العلمية
النظرية—Python لم تمدد شيئاً — كانت لغة برمجية نصية (1991) أصبحت بالصدفة لغة AI لأن NumPy وجدت في 2006، قبل أن تعني "AI" نماذج LLM. القفل لغة هو قفل مكتبة. Mojo (2023، Chris Lattner) يحاول قلبها: بناء جملة Python + مترجم + لا GIL. مبكر جداً للحكم.

٤. منظور الجوّال

ما يستخدمه الجوّال من JS: React Native (Expo، bare)، Capacitor/Ionic (WebView + إضافات أصلية)، NativeScript. JS يعمل على محرك JS (Hermes على Android، JavaScriptCore على iOS) مع جسر للوحدات الأصلية. UI أصلي (React Native) أو WebView (Capacitor).

ما لا يناسب: الأداء الأصلي (عبء الجسر، JSI يساعد لكن لا يلغي)، بدائيات UI الأصلية (أنت تعيد تنفيذ اتفاقيات المنصة)، مراجعة App Store (تطبيقات WebView تواجه تدقيقاً)، تجمع المواهب الذي يعرف Swift/Kotlin من الجامعة.

٤.١ Kotlin / Jetpack Compose (Android الأصلي)

البعدReact Native / JSKotlin + Compose
ما تحسّنهمشاركة الكود مع الويب، إعادة استخدام فريق JSأداء Android أصلي، وفاء المنصة، المسار المبارك من Google
نموذج UIReact (إعلاني، جسر/JSI)Compose (إعلاني، مباشر، إضافة مترجم Kotlin)
اللغةTS/JSKotlin (ثابتة، null-safe، coroutines)
متى تفوزفرق الويب أولاً، عبر المنصات > صقل أصليAndroid أولاً، حرج الأداء، نظام Google البيئي
النظرية—Kotlin لم تمدد Java — بل استبدلت Java على Android بكونها Java أفضل (أمان المعدوم، data classes، coroutines، بويلربليت أقل). باركها Google (٢٠١٧)، جعلها أولوية (٢٠١٩). القيد: Java 6 على Android كانت مجمدة؛ المنصة احتاجت لغة حديثة دون كسر JVM. Kotlin مدت هدف بايت كود JVM، لا لغة Java.

٤.٢ Swift / SwiftUI (iOS الأصلي)

البعدReact Native / JSSwift + SwiftUI
ما تحسّنهمشاركة الكود مع الويبأداء iOS أصلي، وفاء المنصة، المسار المبارك من Apple
نموذج UIReact (جسر/JSI)SwiftUI (إعلاني، مدفوع بالحالة، مُحقق بالمترجم)

متى تفوزالويب أولاً، عبر المنصات > صقلiOS أولاً، نظام Apple البيئي، الأداء، ميزات الخصوصية
النظرية—Swift لم تمدد Objective-C — بل استبدلته. القيد: Obj-C كانت فوقية C مع وقت تشغيل هش؛ Apple أرادت أمان ذاكرة، دلالات قيمة، مترجم حديث. Swift تملك سلسلة الأدوات (LLVM)، وقت التشغيل، المكتبة القياسية. إنها لغة منصة، لا لغة محمولة.

٤.٣ Dart / Flutter (Google "JS لكن مع VM حقيقي ونظام أنواع حقيقي")

البعدReact Native / JSDart + Flutter
ما تحسّنهمشاركة كود الويبقاعدة كود واحدة، UI مثالي البكسل على كل المنصات، لا جسر
نموذج UIمكونات أصلية عبر جسرمحرك رسم خاص (Skia/Impeller)، يرسم كل بكسل
اللغةTS/JSDart (ثابتة، null safety سليم، JIT تطوير / AOT إنتاج)
متى تفوزفريق ويب يذهب للجوّالتطبيقات علامة تجارية أولاً، تصاميم مخصصة، مدمج، سطح مكتب، ويب (نفس الكود)
النظرية—Dart حاولت استبدال JS في المتصفح (٢٠١١، Dart VM في Chrome). فشلت — لا بائع آخر تبناها. تحولت لـ Flutter (٢٠١٧): املك الرسم، املك اللغة، استهدف كل شيء. القيد انعكس: احتكار JS المتصفح كسر لا تكسر؛ لذا ابني مكدس متوازي لا يحتاج محرك JS المتصفح. Dart هي "ما كانت JS لو كان لها نظام أنواع سليم ومترجم AOT".

٥. منظور المدمج / إنترنت الأشياء

ما يستخدمه IoT من JS: Espruino (JS على المتحكمات الدقيقة)، Johnny-Five (Node على المضيف + Firmata على الجهاز)، Tessel، low.js. JS يعمل على أجهزة ≥ 100KB RAM (ESP32، STM32). نموذج حلقة الأحداث يناسب IoT حقاً — المستشعرات أحداث async.

ما لا يناسب: ضغط RAM (V8 تحتاج ~MB)، وقت حقيقي صلب (توقفات GC)، عمر البطارية (مفسر > مُجمّع)، لا مكتبة قياسية للمعدن العاري.

فقرة نظرية واحدة: حلقة أحداث JS في الواقع مناسبة لـ IoT (المستشعرات = أحداث async). الجدار هو RAM، لا نموذج اللغة. C/C++ تفوز لأنها تُجمّع لثنائيات 2KB بوقت تشغيل صفر. Rust الوافد الأحدث: أمان ذاكرة للفييرموير بدون GC. القيد لم ينعكس — فقط اشتد (رقائق أصغر، تنظيم سلامة أكثر). اللغات التي تربح المدمج هي التي تستطيع إسقاط وقت تشغيلها.

٦. منظور الذكاء الاصطناعي / علم البيانات

ما يستخدمه AI من JS: تقريباً لا شيء في طبقة النموذج (PyTorch/JAX/CUDA ليست في JS). كل شيء في طبقة التطبيق: Next.js + Vercel AI SDK + fetch لـ APIs النماذج، LangChain.js، Transformers.js (WASM)، TensorFlow.js (WebGL/WASM). JS مركبة توصيل للنماذج المدربة في مكان آخر.

ما لا يناسب: التدريب (لا CUDA، لا نظام autograd البيئي، لا تدريب موزع)، تينزورات ضخمة (حدود ذاكرة WASM)، تجمع المواهب (كل دكتوراه تتعلم Python).

منافس: Python (طبقة النموذج) / Mojo (المتحدي)

البعدJS (طبقة التطبيق)Python (طبقة النموذج)Mojo (ناشئ)
ما تحسّنهإنتاج النماذج، واجهات ويب، استنتاج Edgeالبحث، التدريب، خطوط أنابيب البيانات، تأليف النماذجبنية جملة Python + أداء أنظمة، لا GIL، تجميع لـ GPU

فقرة نظرية واحدة: AI اختارت Python لأن NumPy وجدت في 2006، قبل أن تعني "AI" نماذج LLM. القفل لغة هو قفل مكتبة، لا قفل لغة. JS تملك طبقة التطبيق لأن الويب هدف التوصيل. Mojo (Chris Lattner، 2023) أول محاولة جادة لقلب القيد: احتفظ ببنية جملة Python، أضف مترجم، أزِل GIL، استهدف المسرعات مباشرة. إن نجحت، هي أول لغة تمد بنية جملة Python لكن تستبدل وقت تشغيلها — عكس استراتيجية TypeScript "تتبخر عند التجميع".

٧. منظور "الآخر": Edge، Serverless، أدوات البناء

حيث JS الافتراضي بالكامل لأن المضيف JS: Cloudflare Workers، Vercel Edge Functions، Deno Deploy، Bun، esbuild/rolldown/Vite (مكتوبة Go/Rust لكن تدفع نظام JS البيئي). وقت تشغيل Edge اختار JS لأن V8 موجود بالفعل، صندوق حماية الأمان موجود بالفعل، والبدء البارد أهم من الأداء المستقر.

منافس: WASM على الحافة. Cloudflare تدعم مكونات WASM؛ Fastly Compute@Edge واصف WASM أولاً. لكن WASM ما زال يحتاج غراء JS لـ DOM/HTTP في المتصفح، والحافة تتقارب على نفس APIs (WinterCG). هنا JS لا منافس حقيقي للغة — WASM شريك، كما في المتصفح.

العكس صحيح أيضاً: عندما لا ينعكس القيد، التمديد يربح. Java مدت بناء جملة C++ لكن راهنت على JVM. C# مدت بناء جملة Java لكن راهنت على CLR. TypeScript تمد بناء جملة JS لكن تتبخر. Kotlin تمد هدف بايت كود JVM لكن تستبدل اللغة. رهان المنصة هو ما يتغير؛ البناء جملة قابلة للتفاوض.

قيد JS الأصلي: لغة برمجية نصية لـ Netscape Navigator 2.0، محمّلة عبر مودم 28k، مكتوبة في 10 أيام. ذلك القيد ذهب. القيود الجديدة (فرق كبيرة، جوّال، حافة، توصيل AI) كل منها ولّد استجابته — TS، RN/Flutter، Workers، Vercel AI SDK. لا أحد استبدل JS لأن لا أحد قلب قيد المتصفح. المتصفح لا يزال يشغل JS فقط (و WASM). ما دام هذا صحيحاً، JS تبقى في المركز والمنافسون يديرون حولها.

ما تغطيه هذه الوثيقة

أين تعمل JS، ما يستخدمه كل مضيف منها، واللغات المبنية لمحاربتها في كل مسار. لا اللغة نفسها (javascript-the-language). لا مشهد أطر الواجهة الأمامية (frontend-camps-survey). لا دواخل رياكت (class-to-hooks-paradigm-shift).
