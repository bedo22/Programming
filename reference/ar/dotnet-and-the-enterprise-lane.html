.NET والمسار المؤسسي

أين يعيش C#/.NET في السوق (المؤسسات، البنوك، الحكومة، مراكز الاستعانة بمصادر خارجية — مصر، الخليج، أوروبا الشرقية)، والإلمام الذي تحتاجه لتتنقل فيه دون أن تصبح مطوّر .NET: حلقة طلب ASP.NET Core مرسّمة واحدًا لواحد على هندسة الخلفية، وجدول ترجمة قراءة من TypeScript إلى C#، وEF Core بصفته الـ ORM الذي تفهمه بالفعل، وأعمار حقن التبعيات الثلاثة، وفروق T-SQL عن PostgreSQL، ومثال عملي يقرأ نقطة نهاية حقيقية من أولها إلى آخرها. اقرأ هذا عندما تذكر لائحة وظيفة أو عقد ما .NET — لتجري المقابلة وتتكامل، لا لتتعلم من جديد.

اللغة: العربية · English

أين يقع هذا. تعلّم هذه الرفوف نظام JavaScript/TypeScript/React بعمق. و.NET هو أكبر عالم خلفية آخر — وبالنسبة لمتعلم في مصر (أو أسواق مشابهة) ليس غريبًا: لوحات الوظائف المؤسسية، والبنوك، والحكومة، والاستعانة بمصادر خارجية من الاتحاد الأوروبي والولايات المتحدة تعمل عليه بكثافة. هذه الوثيقة هي نقطة التقاطع: ما يكفي لقراءة كود C#، وتعيين ASP.NET Core على نماذج ذهنية تملكها بالفعل، ومواصلة محادثة .NET — دون كسر نواة JS لهذه الرفوف:

الجيران وكيف يتقاسموا العمل:

  • JavaScript Across Stacks — يملك جدول التموضع (متى يفوز Node، ومتى يفوز .NET، ولماذا). تضيف هذه الوثيقة إلمام القراءة على جانب .NET من ذلك الجدول.
  • هندسة الخلفية — تملك حلقة الطلب، والمصادقة، والتخزين المؤقت، والمعاملات. ASP.NET Core هو تلك الحلقة بزي مختلف؛ ترسم هذه الوثيقة التطابق قسمًا لقسم.
  • SQL وPostgreSQL — تملك لغة الاستعلام. T-SQL (SQL Server) لهجة؛ تسرد هذه الوثيقة الفروق فقط.
  • API Design — العقود مستقلة عن اللغة؛ ينتج ASP.NET Core عقود REST نفسها بوسمات (attributes).

لماذا توجد هذه الوثيقة

لأن «تخطَّ .NET» نصيحة خاطئة لمكتبة بجمهور مصري. مهمة هذه الرفوف هي الاستكشاف، لا مسار واحد: القارئ الذي يريد عملًا مؤسسيًا/حكوميًا/بنكيًا — سوق الخلفية المهيمن في الاقتصاد الرسمي في مصر والخليج ومعظم أوروبا الشرقية — سيصطدم بـ C#/.NET في لوائح الوظائف والمقابلات وعقود الاستعانة بمصادر خارجية. الموقف الصادق ليس «صِر مطوّر .NET» ولا «تجاهله»: إنه الإلمام القرائي — نماذج الرفوف الذهنية (حلقة الطلب، العقود، المعاملات، الـ ORMs، حقن التبعيات) تنتقل واحدًا لواحد، وقراءة C# ممكنة في عطلة نهاية أسبوع واحدة بعدما تستقر TypeScript في بيتك. تعلّم هذه الوثيقة الترجمة، لا اللغة. ملاحظة نطاق واحدة: هذه ليست دورة C# — لا تدريبات نحوية، ولا دروس أطر عمل؛ العمق موجود في Microsoft Learn ووثائق ASP.NET، المربوطة أدناه.

التعريف — المسار المؤسسي، وماذا يعني الإلمام

.NET منصة تطبيقات مايكروسوفت: لغة C#، ووقت تشغيل CLR (مثل V8 هو وقت تشغيل Node)، وASP.NET Core للويب (معادل .NET لـ Express/Fastify/Next)، وEF Core للوصول إلى البيانات (ORM، مثل Prisma/Drizzle)، وSQL Server بصفته قاعدة بياناته الطبيعية. ليست «لغة» بالمعنى الذي تستخدمه هذه الرفوف للكلمة — إنها مكدس، وموضعها السوقي أهم من نحوها:

الإلمام يعني ثلاثة أشياء، بهذا الترتيب: (1) تستطيع قراءة قاعدة كود C# — تتبع نقطة نهاية من المتحكم إلى قاعدة البيانات؛ (2) تستطيع تعيين كل مفهوم على نماذج ذهنية تملكها بالفعل — لا شيء هنا جديد، أُعيدت تسميته فقط؛ (3) تعرف أين يقع المسار — متى يظهر .NET في حياتك المهنية وماذا يشير إليه. لا يعني كتابة C# للإنتاج أو مطاردة النظام البيئي. إذا اخترت المسار لاحقًا عن قصد، فوثائق الرف الخاصة بالخلفية/API/SQL هي المنهج؛ هذه الوثيقة هي الخريطة التي تجعلها قابلة للنقل.

حلقة الطلب، طبعة C#

النموذج الذهبي لحلقة الطلب في الرف — Request ← Auth ← Logic ← Data ← Response — هو بالضبط ما يشغّله ASP.NET Core. لا شيء هنا جديد؛ كل شيء أُعيدت تسميته:

مفهوم هندسة الخلفية (القسم)كتابة ASP.NET Coreما هو
سلسلة الوسيط (§1، §1b)UseAuthentication()، UseAuthorization()، أصناف وسيط مخصصةخط الأنابيب: كل طلب يتدفق عبر السلسلة بالترتيب — نفس النموذج الذهني لوسيط Express
توجيه طلب إلى معالج (§1)[ApiController] + [Route("api/shipments")] + طرق الإجراءاتصنف واحد لكل مورد؛ كل طريقة نقطة نهاية — مثل ملف موجه بدوال معالج
استخراج المعاملات والتحقق من صحتها (§1)ربط النماذج + [FromBody]، [FromQuery]، التعليقات التوضيحية للبياناتتتحول أجسام الطلبات إلى كائنات مكتوبة تلقائيًا؛ يعمل التحقق عند الربط
عقد الاستجابة (§1، وAPI Design)ActionResult<T>، Problem() (RFC 9457)، مساعدات الحالةreturn Ok(dto)، NotFound()، Problem() — الحالات والأغلفة نفسها التي يصفها وثيقة تصميم API لديك
المصادقة مقابل التفويض (§1d)وسوم [Authorize] + وسيط JWT bearerالوسم = بوابة إذن؛ الوسيط = هوية؛ الانقسام هو نفسه كما في §1d من Backend Engineering
طبقة منطق الأعمال (§1)الخدمات (اصطلاح «طبقة الخدمات»)تبقى المتحكمات نحيفة؛ تحمل الخدمات منطق حلقة الطلب — البنية نفسها التي تستخدمها معالجات Node لديك
انعدام الحالة وقيد بلا خادم (Substrate §Cloud)Azure Functions، ASP.NET Core محوَّل للحاوياتالقواعد نفسها: الحالة تعيش خارج المعالِج؛ بدء التشغيل البارد هو نفس المقامرة

اقرأ أي نقطة نهاية ASP.NET Core هكذا: الوسيط ← المتحكم ← الخدمة ← EF Core ← SQL Server ← الاستجابة. هذا هو الجسر كله.

إلمام قراءة C# — جدول الترجمة من TypeScript

C# ليس غريبًا إذا كانت TypeScript وطنًا — إنه شقيق: كلاهما مكتوبا الأنماط وبلغة أصناف أولًا، مع async/await وأنواع عامة (generics) ومعالجة حديثة للقيم الخالية. يغطي جدول الترجمة ما ستراه فعلًا أثناء القراءة:

TypeScript تعرفهC# ستقرأهملاحظات
interface User { id: number }record User(int Id, string Name) أو class بخصائصالـ records عادة حاملات بيانات غير قابلة للتغيير؛ خصائص PascalCase هي القاعدة
async/await، Promise<T>async Task<T>Task ≈ Promise — الفكرة نفسها، محرك مختلف (انظر ملاحظة async أدناه)
Array.map/filter/reduceLINQ: .Select(...)، .Where(...)، .Aggregate(...)LINQ برمجة وظيفية بنكهة SQL — حدسك في SQL ينتقل مباشرة
const x = ... / let y = ...var (نوع مستنتج)، readonlyvar ليست كتابة ديناميكية — يُستنتج النوع وقت الترجمة
null / السلسلة الاختيارية ?.null، تعليقات القابلية للعدم ?، دمج القيم الخالية ??العادات نفسها: ?? هو COALESCE، ?. هي السلسلة الاختيارية — قواعد NULL من SQL تنطبق على كودك أيضًا

حقن التبعيات يدويًاIServiceCollection، حقن المُنشئيسلّم الإطار الخدمات إلى المنشئات — اقرأها «الإطار يقوم بالحقن عنك»

قاعدة عامة للقراءة: حين تقابل اصطلاح C# غير معروف، اسأل «ما معادله في TypeScript/JavaScript؟» — يوجد واحد، وعادة هو الفكرة نفسها بكلمة مختلفة.

المكان الوحيد الذي تعض فيه «نفس الكلمة، معنى مختلف» فعلًا: async. تعمل JavaScript على حلقة أحداث بخيط واحد؛ يعمل C# على تجمع خيوط مشترك. await الذي تكتبه يبدو متطابقًا، لكن المحرك تحته ليس كذلك — وتظهر فروق المصيدة اللحظة التي تقرأ فيها كود خدمة حقيقي:

JavaScript / NodeC# / .NET
حلقة الأحداث: خيط واحد يتخلل I/Oتجمع الخيوط: يُستعار خيط عامل بينما تعمل مهمة Task
await يعيد التحكم إلى حلقة الأحداثawait يعيد الخيط إلى التجمع؛ يستأنف العمل على خيط من التجمع
لا sync-over-async؛ الحجب يوقف الحلقة كلها.Result / .Wait() يحجبان خيط تجمع — الجمود الكلاسيكي في تطبيقات الويب
setTimeout / setIntervalTask.Delay — الفكرة نفسها، بكتابة مختلفة فقط

اقرأ طرق async Task هكذا: يمكن للعمل أن ينتظر دون حجب خيط. وعامل .Result كعلامة خطر تستحق إعلانها بصوت عالٍ — إنه معادل C# لـ setInterval طويل العمر يسرب الذاكرة: يعمل حتى لا يعمل.

EF Core — الـ ORM الذي تفهمه بالفعل

هندسة الخلفية §1e يمنحك قرار الـ ORM مقابل SQL الخام؛ EF Core مثال كامل المواصفات على ذلك القرار. ما تحتاجه لتقرأ:

مفهوم الـ ORM (من §1e في Backend / وثيقة SQL)كتابة EF Coreما الذي تراقبه
تعيين المخططDbContext + خصائص DbSet<T>كل DbSet جدول؛ الصنف هو شكل الصف
الترحيلاتdotnet ef migrations add / database updateقواعد ترحيل نمذجة البيانات تنطبق دون تغيير
الاستعلامLINQ: context.Shipments.Where(s => s.CustomerId == id)يتعامل LINQ-to-SQL إلى لغة الاستعلام التي تعرفها بالفعل؛ نموذج WHERE/JOIN نفسه ينطبق
مصيدة N+1التحميل الكسول (معطّل افتراضيًا) مقابل .Include(...)خصائص التنقل غير المضمّنة = مشكلة N+1 من SQL §JOINs، بثوب LINQ
منفذ الهروب الخامFromSqlRaw / ExecuteSqlRawالقواعد نفسها لـ SQL الخام في Node: بارامتر أو تُحقن

القطعة الوحيدة الجديدة الشكل حقًا هي تتبع التغييرات: يراقب EF Core الكائنات التي حمّلتها ويكتب فقط ما تغيّر — راحة ORM تحاكيها ORMs في Node بدرجات متفاوتة. حين تقرأ context.SaveChanges()، فهذه هي لحظة «اكتب المعاملة».

حقن التبعيات وشكل الإطار

ASP.NET Core مبني حول حقن المُنشئ: تُسجَّل الخدمات مرة واحدة، ويبني الإطار كل شيء عنك. ترتبط الأعمار الثلاثة مباشرة بنقاش انعدام الحالة في الرف (Backend §7، Substrate §Cloud):

العمرما يعنيهترجمة الرف
Singletonنسخة واحدة لعمر المعالِجمثل ثابت على مستوى الوحدة — جيد للإعداد عديم الحالة، خطير للحالة (قاعدة الذاكرة داخل المعالِج في بلا خادم)
Scopedنسخة واحدة لكل طلب HTTPسياق نطاق الطلب — العمر الطبيعي لـ DbContext ولأي شيء مربوط بطلب واحد
Transientنسخة جديدة عند كل حقنمساعدات عديمة الحالة رخيصة — مثل استيراد دالة نقية

قراءة أي طبقة خدمات .NET: تتبع المُنشئ. كل ما يطلبه الصنف يوفره الإطار — وتخبرك تسميات الأعمار ما إذا كانت الحالة المشتركة اختيارًا متعمدًا أم حادثًا في الانتظار (مفرد يحمل حالة لكل طلب هو الخطأ الكلاسيكي في .NET، وهو نفس صنف الخطأ كذاكرة تخزين مؤقت على مستوى الوحدة داخل دالة بلا خادم).

خريطة سوق .NET — أين يقع المسار فعلًا

بالنسبة لمتعلم في مصر (أو أسواق مشابهة)، السؤال العملي هو: متى يظهر .NET فعلًا في حياتك المهنية؟

أعمال التكامل (أي عميل خلفيته .NET)تستهلك واجهات REST الخاصة بهم — التي ينتجها ASP.NET Coreمعرفتك في API Design هي المهارة كلها؛ .NET غير ذي صلة أبعد من قراءة وثائقهم
الشركات الناشئة، العمل الحر، الوكالاتNode، Python، PHP/WordPressالمسارات التي تخدمها هذه الرفوف غالبًا — نادرًا ما يظهر .NET

الخط الاستراتيجي، من التموضع الخاص بالرف: .NET يفوز حيث توجد عقود مايكروسوفت المؤسسية؛ Node يفوز حيث توجد فِرق JavaScript. لا ادعاء منهما خطأ؛ يصفان سوقين مختلفين. إذا كان السوق المؤسسي هو الذي تريده، فوثائق الرف للخلفية/API/SQL هي المنهج القابل للنقل — النماذج الذهنية تنتقل؛ يتغير النحو فقط.

فك شفرة الإصدار — ماذا يعني «.NET» في لائحة وظيفة

لائحة وظيفة تقول فقط «.NET» غامضة، لأن النظام البيئي مر بثلاثة أسماء لنفس خط الإنتاج. قراءة اللائحة صحيحًا جزء من الإلمام:

ما تقوله اللائحةما هو فعلًا
.NET Framework 4.8 / «ASP.NET»الكلاسيكي الخاص بنظام Windows (2002–2019، مجمّد عند 4.8). البنوك والأنظمة الحكومية القديمة ما زالت تعمل عليه — ستقرؤه كإرث، لا تكتبه
.NET Core 2.x / 3.1إعادة الكتابة عبر المنصات (2016–2020). علامة عصر الترحيل غالبًا الآن
.NET 5 / 6 / 8.NET الحديث — أُعيدت تسمية Core بإسقاط «Core». الدعم طويل الأمد (LTS) بالأرقام الزوجية (6، 8)؛ 8 هو الحالي، و10 هو الخط الزوجي التالي
«.NET» بلا رقمغامض بحكم التعريف — اسأل عن الرقم في المقابلة. «أي .NET؟» سؤال مقابلة حقيقي، ليس خدعة

قاعدة إبهام واحدة: الرقم الزوجي = دعم طويل الأمد، والفردي = أحدث الميزات. إذا استهدفت قاعدة كود net8.0، فهي الخط الحديث — اقرأها بهذه الوثيقة؛ إذا قالت net48، فتوقع أنماط إرث وشكل ASP.NET أقدم.

SQL Server — لهجة T-SQL

تفتح شِركات .NET افتراضيًا على SQL Server، وT-SQL هي SQL التي تعرفها بلكنة مختلفة. فروق القراءة، في جدول واحد:

PostgreSQL (الرف)SQL Server / T-SQL
LIMIT n OFFSET mTOP n (أو OFFSET ... FETCH NEXT n ROWS)
now()، interval '7 days'GETDATE()، DATEADD(day, -7, GETDATE())
bigserial زيادة تلقائيةIDENTITY(1,1)
ON CONFLICT ... DO UPDATEMERGE (أو INSERT ... WHERE NOT EXISTS)؛ لا UPSERT مباشر حتى الإصدارات الحديثة
مصفوفات text[]، JSONBلا مصفوفات؛ JSON بدعم أضعف — منطقة راحة SQL Server هي البيانات العلائقية المنظمة
ILIKE، تعبيرات نمطية ~LIKE (عدم حساسية الحالة يعتمد على الترتيب)، لا تعبيرات نمطية أصلية
pg_dump / psqlsqlcmd، SSMS، BACKUP DATABASE

الـ 90% المشتركة — تشريح SELECT، وJOINs، وGROUP BY، والدوال النافذة (يدعمها T-SQL جيدًا)، والمعاملات — هو بالضبط ما يعلّمه SQL وPostgreSQL. اقرأ أي استعلام T-SQL كاللغة نفسها بهذه التحويلات الستة.

متى لا تختار .NET

الإلمام ليس دعوة. لخريطة المسار وجه معكوس — الحالات التي يكون فيها .NET الأداة الخاطئة، وحيث «لماذا هذا .NET؟» هو رد الفعل الصحيح:

  • الأعمال الصغيرة / عمل العملاء: موقع WordPress، صفحة هبوط، متجر صغير — إنترنت CMS موجود لأن المؤسسات تشتري أكثر من حاجتها. .NET عبء، لا قدرة.
  • تكرار الشركة الناشئة: لغة واحدة عبر المكدس، نشر سريع، فِرق صغيرة — يفوز Node/TS بحوض التوظيف وسرعة التكرار.
  • فريق من شخص واحد / العمل الحر: وزن النظام البيئي (Visual Studio، Azure، ملفات الحلول، طقوس المشروع) ضريبة يدفعها مطور فردي بلا مقابل.
  • عمل الواجهة في الحافة / بلا خادم: مسار Next.js في الرف — Next.js، Vercel، Supabase — ليس له فصل .NET.

الإشارة التي تبحث عنها: عقود مايكروسوفت المؤسسية القائمة، وأنظمة الامتثال، وآفاق صيانة تمتد عشر سنوات. هناك كسب .NET مكانه — وهناك يدفع قراءته ثمنها.

مثال عملي — قراءة قاعدة كود .NET

نقطة نهاية ASP.NET Core بشكلها الواقعي، تُقرأ بعيون الرف. نقطة النهاية: GET /api/shipments/{id} — نفس عالم تتبع الشحنات كما في SQL §المثال العملي:

// 0. The entry point — Program.cs: the first file you open
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<AppDbContext>(o =>
    o.UseSqlServer(builder.Configuration.GetConnectionString("Shipments")));
builder.Services.AddScoped<IShipmentService, ShipmentService>();   // DI registration
var app = builder.Build();
app.UseAuthentication();   // middleware pipeline: runs in this order, wraps the request
app.UseAuthorization();
app.MapControllers();      // route attributes now work
app.Run();

// 1. The controller — thin, like a Node route handler with validation
[ApiController]
[Route("api/shipments")]
public class ShipmentsController : ControllerBase
{
    private readonly IShipmentService _svc;          // ← DI hands the service in

    public ShipmentsController(IShipmentService svc) => _svc = svc;

    [HttpGet("{id:long}")]                            // GET /api/shipments/42
    public async Task<ActionResult<ShipmentDto>> Get(long id)
    {
        var shipment = await _svc.GetByIdAsync(id);   // ← the request-loop logic lives here
        return shipment is null ? NotFound() : Ok(shipment);
    }
}

// 2. The service — the request loop, in the "service layer" convention
public class ShipmentService : IShipmentService
{
    private readonly AppDbContext _db;                // ← EF Core's DbContext (scoped)

    public async Task<ShipmentDto?> GetByIdAsync(long id) =>
        await _db.Shipments                          // a DbSet — the table
            .Where(s => s.Id == id)                  // WHERE — LINQ translates to SQL
            .Select(s => new ShipmentDto(s.Id, s.TrackingNumber, s.Status))
            .SingleOrDefaultAsync();                 // one row, or null → NotFound
}

// 3. The DTO — the API contract (api-design: the response shape is a deliberate artifact)
public record ShipmentDto(long Id, string TrackingNumber, string Status);

أين تبدأ القراءة — الملفات الثلاثة الأولى:

  • Program.cs — نقطة الدخول: تسجيلات حقن التبعيات وخط أنابيب الوسيط، بالترتيب الذي تعمل به.
  • appsettings.json — الإعدادات: سلسلة الاتصال، وأعلام الميزات، وإعدادات التسجيل.
  • *.csproj — بيان الاعتماديات (package.json الخاص بـ .NET)؛ يخبرك سطر <TargetFramework>net8.0</TargetFramework> بأي نسخة من القصة تقرأ.

اقرأ من أولها إلى آخرها: يربط التوجيه ← يطلب المتحكم من الخدمة ← يترجم EF Core LINQ إلى SQL الذي تعلمته ← يجيب SQL Server ← يخرج DTO. لكل مفهوم في هذا الملف بيت في الرف — Backend §1 (الحلقة)، §1e (الـ ORM)، API Design (العقد)، SQL (الاستعلام تحته). هذا هو بيت القصيد من الوثيقة: لا شيء هنا جديد؛ كل شيء أُعيدت تسميته.

الملخص — خريطة المسار

اطبع هذا. إنه الوثيقة كلها في تسعة أسطر:

#السطر
1.NET = C# + CLR + ASP.NET Core + EF Core + SQL Server: مكدس، وموضعه السوقي أهم من نحوه.
2المسار: المؤسسات، البنوك، الحكومة، الاستعانة بمصادر خارجية (مصر، الخليج، أوروبا الشرقية). لا الشركات الناشئة، لا العمل الحر، لا إنترنت CMS.
3الحلقة متطابقة: الوسيط ← المتحكم ← الخدمة ← EF Core ← SQL Server ← الاستجابة. لا شيء جديد، أُعيدت تسميته فقط.
4TypeScript ← C# ترجمة لا تحويل: records، Task/async، LINQ، ?? — جدول واحد، بلا مفاجآت.
5EF Core هو قرار الـ ORM من §1e في Backend؛ .Include هو مصيدة N+1 بثوب LINQ.
6أعمار الحقن: singleton = معالِج، scoped = طلب، transient = جديد — قواعد انعدام الحالة تنطبق.
7T-SQL هو SQL الذي تعرفه بستة تحويلات: TOP، GETDATE، IDENTITY، MERGE، لا مصفوفات، الترتيب.
8لا تختَر .NET للمواقع الصغيرة أو الشركات الناشئة أو العمل الفردي؛ ولا ترفضه حيث تشغّله المؤسسات.
9الإلمام قبل الطلاقة: اقرأ الكود، وعيّن المفاهيم، واعرف المسار — ثم قرر إن كنت تريده أصلًا.
