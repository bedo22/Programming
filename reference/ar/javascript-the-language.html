جافاسكريبت: اللغة — التاريخ، التصميم، ونموذج التشغيل

كيف أصبحت JS هي JS: صفقة نتسكيب/صن 1995، سباق برندان إيك في 10 أيام، موكا → لايف سكريبت → جافاسكريبت → إيكماسكربت، نموذج البروتوتايب، حلقة الأحداث، التزامن أحادي المسار، ولماذا أصبحت لغة برمجية نصية لتحقق النماذج هي اللغة الوحيدة التي تعمل أصلياً في كل متصفح. وثيقة تأسيسية لباقي رف المراجع.

لمن هذه الوثيقة: مطوّرون يستطيعون كتابة JS لكن لا يستطيعون دائمًا التنبؤ بها — أي مَن فوجئ بترتيب حلقة أحداث، أو this ضائع، أو تسريب تعديل. تُقرأ مع سلسلة الدروس لتفاصيل الآليات.

لماذا توجد هذه الوثيقة

وثائق المراجع الأخرى (نموذج رياكت، تطور Angular، Next.js العميق، مسح المعسكرات) تعامل JS كمسلمة. هذه الوثيقة تتراجع وتسأل: ما هي JS، ولماذا تبدو هكذا، وما الرهانات التصميمية التي جعلتها اللغة التي تعمل في كل مكان؟ شقيقة لـ ما هي الحالة (التي تغطي نظرية البرمجة عموماً) وسياق أب لـ الانتقال من الكلاسات إلى الخطافات. وثيقتها الشقيقة عبر المنصات (جافاسكريبت عبر المنصات) تغطي أين تعمل JS ومن يحاربها في كل مسار.

كيف تستخدم هذه الوثيقة

ترتيب القراءة: مستقلة. جلسة واحدة. هذه الوثيقة ليست درس JS — سلسلة الدروس بالفعل هي (من الدرس ٠٠٠١ — اللغة العرضية — إلى الدرس ٠٠٢٢ — العالم الحقيقي). هذه الوثيقة ليست وثيقة رياكت — class-to-hooks-paradigm-shift بالفعل هي. هذه الوثيقة هي القطعة المفقودة: تاريخ اللغة، منطق التصميم، ونموذج التشغيل، مكتوبة لتستطيع قراءة أي قاعدة كود JS دون أن تسأل "لماذا فعلوها هكذا؟" على مستوى اللغة. المرجع: المصطلحات — مفردات مشتركة عبر جميع وثائق المراجع.

خريطة الرافعة — أين يتركّز العمل فعليًا

لخريطة الدلالات أدناه أحد عشر بُعدًا، لكن عمل JS اليومي لا يتوزع بالتساوي عليها. تدرّجات عملية تقريبية، مستمدة مما يعاقب عليه جدول أنماط الفشل أكثر شيوعًا وما تتطلبه قراءة الشيفرة فعليًا:

التدرّجالدلالاتما تغطيه

العشرة أيام في مايو ١٩٩٥

مايو ١٩٩٥. نتسكيب نافيجيتور ١.١ يُشحن. الويب مجرد HTML ساكن. مارك آندريسن يريد المتصفح قابلاً للبرمجة — ليس فقط لعرض المستندات، بل للتفاعل مع المستخدم. يكلف برندان إيك، مبرمج أنظمة عمره ٣٤ سنة انضم لنتسكيب في أبريل، ببناء لغة برمجية نصية للمتصفح. القيود: يجب أن تعمل في المتصفح، يجب أن تكون سهلة لغير المبرمجين (مصممون، مؤلفو HTML)، يجب أن تُشحن في نتسكيب ٢.٠ بحلول سبتمبر.

لدى إيك ١٠ أيام لإنتاج نموذج أولي عامل. يستلهم من خطين:

  • Scheme (Lisp) — دوال من الدرجة الأولى، إغلاقات لفظية، نواة صغيرة. إيك أراد هذا.
  • Java — تحالف نتسكيب/صن يعني "بنية جملة شبيهة بـ Java" كان مطلب إدارة. الأقواس { }، الفواصل المنقوطة ;، new، typeof — كلها على شكل Java.

سُمِّي النموذج الأولي Mocha. شُحن في نسخة بيتا من نتسكيب نافيجيتور ٢.٠ كـ LiveScript. أُعيدت تسميته JavaScript في ديسمبر ١٩٩٥ — مصافحة تسويقية بين صن/نتسكيب: "Java للمؤسسات، JavaScript للمتصفح". الاسم تسبب في ٣٠ سنة من الالتباس. Java و JavaScript تتشاركان البنية (الأقواس المعقوفة) ولا شيء تقريباً غير ذلك.

مصدر أولي → برندان إيك، FAQ: Why is JS designed the way it is? (٢٠١١): "أردت لغة شبيهة بـ Lisp لكن اضطررت لاستخدام بنية جملة شبيهة بـ Java لتمرير موافقة الإدارة. تحت أقواس { } ينبض قلب حساب لامدا في جسد على شكل C."

لماذا لغة جديدة، لا ابليت Java ولا امتداد C++

النظرية التي سألت عنها: لماذا إنشاء لغة جديدة بدلاً من تمديد Java أو C++؟ الجواب هو قيود المنصة.

  • Java applets كانت قادمة بالفعل (١٩٩٥). كانت لديها JVM ثقيلة، خطوة تجميع، كتابة ساكنة، صندوق حماية. كانت لـ تطبيقات داخل المتصفح — ثقيلة، بطيئة البداية، مبالغة لـ "تحقق من هذا النموذج قبل الإرسال".
  • C++ — لا أحد يشحن مترجم C++ لمتصفح. لا تجميع قمامة، إدارة يدوية للذاكرة، لا صندوق حماية آمن. المتصفح يحتاج لغة لا تُسقط العملية.
  • المنصة تحتاج غراء. قشرة برمجية نصية: تحوّر DOM، تتعامل مع أحداث، تحقق نماذج، تتحدث للخادم (لاحقاً: XMLHttpRequest). لغات الغراء مكتوبة ديناميكياً، ذات تجميع قمامة، مفسرة، متسامحة. Java و C++ لا شيء من هذه.

النمط الذي يتكرر: المنصة تستحق لغة مصممة لقيودها، لا ورثة من منصة مختلفة. هذه نفس النظرية التي تبرر لاحقاً TypeScript (ترقية JS لصيانة الفرق الكبيرة، لا بديل)، Go (بديل C++ مصمم للخوادم الشبكية، لا لغة أنظمة عامة)، Rust (بديل C++ يحل أمان الذاكرة بدون GC). القيود تغيرت — اللغة تغيرت.

التصميم: نموذج البروتوتايب، لا الكلاسات

اختار إيك البروتوتايبات لا الكلاسات. التأثير: Self (حفيد Smalltalk، مبني على البروتوتايب، من مختبرات صن). في نظام البروتوتايب، الكائنات تورث مباشرة من كائنات أخرى — لا كلاس ككيان منفصل. تنشئ كائناً، يصبح بروتوتايب لآخرين. Object.create(proto) هو البدائي.

new في جافاسكريبت + دالة منشئة + .prototype طبقة نحوية رقيقة فوق هذا:

// سلسلة البروتوتايب في العمل
function Animal(name) { this.name = name; }
Animal.prototype.speak = function() { console.log(this.name + ' makes a sound'); };

const dog = new Animal('Dog');
dog.speak(); // Dog makes a sound

// dog.__proto__ === Animal.prototype
// Animal.prototype.__proto__ === Object.prototype
// Object.prototype.__proto__ === null

كلمة class في ES6 (٢٠١٥) سكر نحوي فوق البروتوتايبات — لا نظام كلاسات كامل. لا تُدخل حقولاً خاصة (جاءت لاحقاً، ٢٠٢٢)، لا تغير التوريث الأحادي، لا تضيف إرسال متعدد. تخفي التفويض. عندما تقرأ class Dog extends Animal، سلسلة البروتوتايب لا تزال هناك تحته. فهم نموذج البروتوتايب مهم لأن السكر يتسرب: ربط this، استخراج الدوال، Object.getPrototypeOf، __proto__ كلها تكشف الآلية.

التصميم: دوال من الدرجة الأولى، إغلاقات، قلب حساب اللامدا

سلالة Scheme/Lisp. دوال جافاسكريبت قيم — يمكن إسنادها، تمريرها، إرجاعها، إنشاؤها أثناء التشغيل. هذا يمكّن:

  • دوال رتبة أعلى — map/filter/reduce تأخذ دوالاً كمعاملات.
  • إغلاقات لفظية — دالة "تلتقط" نطاقها المحيط. function outer() { let x = 1; return function inner() { return x++; }; } — inner تتذكر x بعد عودة outer.
  • كيري (Currying) — تطبيق جزئي بإرجاع دوال تأخذ المعامل التالي.

هذه ليست "ميزات أضيفت لاحقاً". كانت هناك في النموذج الأولي ذي الـ ١٠ أيام لأن إيك نفذ حساب اللامدا مباشرة. كلمة function هي لامدا. درس الإغلاقات يغطي الآليات؛ هذه الوثيقة تغطي لماذا.

مصدر أولي → برندان إيك، JavaScript at 20 (٢٠١٥): "قلب حساب اللامدا كان هناك منذ اليوم الأول. الجسد على شكل C كان التنازل."

النماذج الذهنية — كيف يفكر المطورون فعلاً حول حلقة الأحداث

معظم أخطاء JS ليست أخطاء صياغة — بل أخطاء نماذج ذهنية حول متى يعمل الكود. الحلقة نفسها هي الجواب، لكن كيف يتخيل المطور الحلقة يحدد ما إذا كان يتنبأ صحيحاً. النماذج الذهنية الأربعة الأكثر شيوعاً عملياً:

النموذج الذهنيما يعتقده المطورأين ينكسردليل التصحيح
«متزامن حتى يثبت العكس» JS تعمل من الأعلى للأسفل؛ async/await «ينتظر» فقط في السطر التحويرات بعد await تبدو وكأنها تحدث «قبل» أن يحل الوعد المنتظَر — ينسى المطور أن الاستمرارية مجدولة «لماذا ما زالت x القيمة القديمة بعد أن انتظرت الإسناد؟» ← الإسناد في مهمة دقيقة بعد أن استُئنف المنتظر فعلاً
«setTimeout(fn, 0) تعني "فوراً"» 0ms = الآن المعاود يعمل بعد المهمة الحالية وكل المهام الدقيقة والعرض؛ للصفحات الثقيلة يمكن أن تكون مئات المللي ثانية «لماذا لم يشتعل معاودي؟» ← افحص الطابور؛ العرض والمهام الدقيقة تُفرَّغ أولاً
«await يفك القيمة» await p يعطيك قيمة p، كإسناد متزامن await يسلم المهمة الحالية لطابور المهام الدقيقة؛ يعود التحكم لحلقة الأحداث أولاً. أي شيء عمل بين الانتظار والاستئناف سيرصد حالة جزئية «لماذا رأى معاود منافسي الحالة القديمة؟» ← عمل في فجوة المهمة الدقيقة
«كل المعاودات غير متزامنة» كل ما تفعله JS «قائم على المعاودات»، فلا يهم الترتيب الكود المتزامن يعمل حتى الاكتمال أولاً؛ فقط حين يفرغ المكدس تعمل المهام المجدولة. الترتيب يهم داخل المهمة «لماذا يقرأ معاودي حالة من مهمة ظننت أنها عملت لاحقاً؟» ← عمل داخل مهمة سابقة، لا بعدها

الانضباط. النموذج «الصحيح» هو: مكدس واحد يعمل حتى الاكتمال؛ المهام المجدولة أثناء التشغيل تُعالَج بترتيب الطابور بعد فراغ المكدس؛ المهام الدقيقة تُفرَّغ قبل المهمة الكبرى التالية. بمجرد استيعاب هذا، تنهار النماذج الأربعة أعلاه إلى واحد. الجزء الصعب أن اللغة تسمح لك بكتابة كل واحد من النماذج الأربعة الخاطئة وتنتج مخرجات تبدو معقولة حتى يظهر الخلل في الإنتاج. لهذا توجد أقسام «النموذج الذهني» في كل وثيقة JS جادة — ليس لأن النماذج الأربعة موجودة، بل لأن الانضباط الواحد الذي يحل محلها هو مهارة بحد ذاتها، واللغة لا تفرضه عليك.

بيئة المضيف، لا اللغة

أكبر بصيرة في JS: JS ضيف في مضيف. مواصفة اللغة (إيكماسكربت) تعرف النواة — البنية، الأنواع، الكائنات، الدوال، حلقة الأحداث. المضيف يوفر كل شيء آخر:

المضيفالعموميات التي يوفرها
المتصفحwindow، document، fetch، localStorage، WebGL، WebAssembly
Node.jsglobal، require/import، fs، net، process، Buffer
DenoDeno، Deno.serve، Deno.readFile، APIs قياسية للويب

لهذا window غير موجودة في Node، fs غير موجودة في المتصفح، والكود "الموحد" (isomorphic) ينكسر عندما يفترض عامومية مضيف. اللغة واحدة؛ المضيف يتغير. الدرس: عند قراءة JS غير مألوف، حدد المضيف أولاً. require → Node/CommonJS. import + Deno → Deno. window → متصفح.

خريطة الدلالات الأساسية — ما يعرّفه ECMAScript نفسه

جدول المضيف أعلاه يعطي البيئة. هذا القسم يرسم اللغة — النموذج الدلالي الذي تحدده ECMAScript باستقلال عن أي مضيف: الأنواع، المساواة، النطاق، this، البروتوتايبات، الوحدات، التكرار، الأخطاء، والذاكرة. هذا ليس درساً تعليمياً؛ الدروس تمشي في الآليات. هذا هو نظام التصميم تحتها: كيف يتصرف كل بُعد، لكي تستطيع حين تقرأ برنامجاً أن تتنبأ به. جملة واحدة تحمل النموذج كله:

JavaScript ديناميكية الأنواع، معجمية النطاق، قائمة على البروتوتايب، وأحادية المسار. دوالها قيم من الدرجة الأولى، وكائناتها تفوّض عبر سلاسل البروتوتايب، وتزامنها تقوده حلقة أحداث — لا خيوط ذاكرة مشتركة.

الأنواع — البدائيات مقابل الكائنات

JavaScript لها عائلتان من القيم. كل ما ليس كائناً فهو بدائية:

الفئةالقيمالسلوك

ثلاث حقائق تشكل كل برنامج:

  • الدوال كائنات — يمكن إسنادها وتمريرها وإعطاؤها خصائص (انظر الدوال من الدرجة الأولى). المصفوفات كائنات — بخصائص length خاصة تتبع أعلى فهرس، لا عدد عناصر.
  • typeof null === "object" خلل تاريخي (وسم نوع null خُزِن كوسم الكائن لعدم وجود أفضل). محفوظ للأبد — الويب لا يمكن أن ينكسر.
  • الغلافات موجودة لكن يجب أن تبقى غير مرئية. new String("x") وnew Number(1) وnew Boolean(true) تنشئ أغلفة كائن تتصرف غالباً كبدائيات لكنها تُقارن بالمرجع — new Number(1) === 1 هي false. لا تُنشئها صراحةً أبداً؛ دع البدائيات تلتف تلقائياً عند استدعاء الدوال ("abc".toUpperCase()).

الإكراه ليس عشوائياً — إنه محدد بالكامل. صُمم للغة سكربت صغيرة في 1995، لذا كثير من الحالات تفاجئ مطورين تربوا على لغات أصرّ. ابدأ بحفظ اختيار العوامل، ثم النموذج الذهني للإكراه.

قواعد إبهام تغطي الكود الحقيقي:

  • فضّل === افتراضياً. المطور «الرخو» الذي يكتب == يختار إكراهاً لم يقصده عادة.
  • استخدم == فقط حيث يكون الإكراه هو النقطة — مثلاً فحص null أو undefined: x == null يغطيهما معاً.
  • اجعل التحويلات صريحة. Number(x) وString(x) وBoolean(x) — لا +x ولا "" + x ولا !!x. الصريح قابل للبحث ويكشف النية.
  • الصدق راحة رقمية، لا نوع. 0 و"" وNaN وnull وundefined وfalse زائفة؛ كل ما عداها — بما فيه "0" و[] — صادق. [] == false هي true لأن [] يُكرَّه إلى "" ثم 0.

النطاق، الرفع، المنطقة الميتة الزمنية، والإغلاقات

النطاق يجيب «أي المتغيرات يستطيع هذا الكود رؤيتها؟» وهو معجمي — تحدده كتابة الكود لا تشغيله. هذه الحقيقة الواحدة تشغّل الإغلاقات، وعبرها المعالجات والوحدات وخطافات React.

حلقة var-مقابل-let هي أوضح برهان:

// var: one shared binding — all callbacks see 3
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));
}
// 3 3 3

// let: a fresh binding per iteration — 0, 1, 2
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i));
}
// 0 1 2

الإغلاقات ليست «ميزة أُضيفت لاحقاً» — إنها في النصف الأعلى من فئات النموذجين في العالم الحقيقي كلاهما: تتذكر النطاق حيث أُنشئت لا حيث تعمل. الآليات في درس الإغلاقات؛ هنا النقطة هي لماذا توجد الإغلاقات: إنها إجابة اللغة عن «كيف تحتفظ دالة بوصول إلى البيانات التي تحتاجها بعد أن ينهي منشئها عمله؟»

this — يحدده موضع الاستدعاء

معظم اللغات تعطي this معنى معجمياً. JavaScript لا تفعل — إلا دوال الأسهم. القاعدة الوحيدة:

this يُربط بـ كيف تُستدعى الدالة (موضع الاستدعاء)، لا أين عُرّفت. دوال الأسهم هي الاستثناء الوحيد: لا تملك this خاصاً بها وترث واحداً من النطاق المحيط.

نوع الاستدعاءقيمة this
استدعاء عادي: fn()undefined في الوضع الصارم / الوحدات؛ وإلا فالكائن العام
استدعاء دالة: obj.method()الكائن قبل النقطة
منشئ: new Foo()كائن مُنشأ حديثاً
صريح: fn.call(x) / fn.apply(x) / fn.bind(x)الكائن الممرر صراحةً
دالة سهممعجمي — ترث من النطاق المحيط

النتيجة التي تعض الكود الحقيقي هي استخراج الدالة: إخراج obj.method وتمريره لمكان آخر يغير موضع الاستدعاء، فيتغير this. لهذا احتاجت مكونات الكلاس في React إلى this.handleClick = this.handleClick.bind(this) ولهذا الإصلاح دوال أسهم أو bind. القاعدة نفسها تفسر خلل «فقدان this» الكلاسيكي في المعالجات.

عواقب عملية لامتلاك البروتوتايب:

  • البحث بالخاصية مسير سلسلة، لا بحث. إضافة Animal.prototype.speak بعد إنشاء النسخ ما زال يعمل — تجدها النسخ على السلسلة وقت الاستدعاء.
  • افحص الخصائص الذاتية حين يهم. obj.hasOwnProperty(k) أو Object.keys(obj)، إذا كانت المفاتيح الموروثة ستكسر منطقك.
  • الواصفات والمُحصِّلات/المُعيِّنات. Object.defineProperty يعطي أي خاصية مُحصِّلاً/مُعيِّناً وأعلام writable/configurable. مُحصِّل الكلاس get age()/set age() يُجمَّع إلى واصف.
  • التجميد والختم سطحيان. Object.freeze(obj) يمنع إضافة/إزالة/تغيير الخصائص على المستوى الأعلى فقط — الكائنات المتداخلة تبقى قابلة للتغيير.
  • تلوث البروتوتايب ثغرة يوم صفر حقيقية. إذا دُمجت مفاتيح غير موثوقة بعمق (مثل {...source}) وأسند الدمج إلى Object.prototype، فكل كائن في زمن التشغيل يمكن أن يكتسب سلوكاً يتحكم به المهاجم. خفّفه بـ JSON.parse أو قوائم مفاتيح صارمة أو Map أو دامج يقرأ فقط. مكتبات مثل lodash شحنت ثغرات CVE في merge من هذا بالضبط.

معالجة الأخطاء — مَرمية كقيم

أخطاء JavaScript كائنات: يمكن بناؤها ورميها واللحاق بها وتصنيفها فرعياً وإعطاؤها خصائص وفحصها. تلك القوة سيف ذو حدين — إنها الآلية نفسها للأخطاء البسيطة ولتسلسلات أخطاء بمقياس الأطر.

  • throw أي شيء؛ لكن فضّل رمي قيم بشكل Error لتبقى تتبعات المكدس.
  • try/catch/finally — catch يعمل عند الرمي، finally يعمل دائماً (تنظيف، تسجيل).
  • أنواع الأخطاء المدمجة — Error وTypeError وReferenceError وSyntaxError وRangeError وURIError؛ المجمّعات وزمنات التشغيل تحفظ النسب صحيحاً.
  • أصناف الأخطاء المخصصة — class ApiError extends Error مع super(message)، ثم err instanceof ApiError في المصب.
  • تتبعات المكدس — تُلتقط عند البناء؛ قراءتها تحتاج أدوات المضيف (err.stack).
  • الفشل غير المتزامن نمط فشل مختلف. throw خارج try في سلسلة وعود يصبح رفضاً غير معالَج — لا يحطم الصفحة افتراضياً بالطريقة التي يحطمها استثناء غير ملتقط، ويمكن أن يختفي بصمت. عالِج الرفض عند الحد (.catch / try/await)؛ وسجّل معالجات الرفض العامية للعملية/المتصفح كشبكة أمان.
  • Promise.allSettled / AggregateError — حين يجب أن يتعايش عدة فشل ونجاح، allSettled يعطيك نتائج لكل وعد؛ وPromise.any/AggregateError لـ«نجح واحد على الأقل».

الوضع الصارم — تنظيف اللغة الذاتي

أضاف ES5 (2009) الوضع الصارم كخيار اشتراك للكود الجديد دون كسر القديم:

  • يعطّل الأخطاء الصامتة (الإسناد لخصائص للقراءة فقط يرمي).
  • يمنع العاميات العرضية (x = 1 غير المصرَّح يرمي الآن).
  • يجعل this في الدوال العادية undefined بدل الكائن العام (انظر خريطة الدلالات الأساسية) — يلتقط مزيداً من أخطاء مواضع الاستدعاء.
  • يقتل فخاخ صياغة قديمة قليلة؛ حظر with والثماني بادئة 0.

في الكود الحديث لا تكتب "use strict" بنفسك أبداً تقريباً: الوحدات والكلاسات صارمة افتراضياً. الوحدات دائماً؛ الكلاسات دائماً. هذا ضبط دقيق يجعل السلوكيات المصلحة تصل حتى للكود الذي لم يشترك أبداً.

ما لا تعرّفه ECMAScript: DOM، CSSOM، fetch، المؤقتات، console، نظام الملفات، مقابس الشبكة، متغيرات البيئة، تخزين المتصفح، عمال الويب، عمال الخدمة. كلها مرافق مضيف (بيئة المضيف). حين «لا يعمل» الكود في بيئة جديدة، أول سؤال هو أي واجهة مضيف افترضها.

لماذا المحركات مهمة للقارئ: JIT يعني خصائص الأداء تعتمد على وقت التشغيل. المقاييس الدقيقة تكذب. "JS بطيئة" قديمة بـ ٢٠ سنة — V8 يجمع المسارات الساخنة لشفرة آلة. لكن: تسخين JIT موجود، وإلغاء تحسين يحدث، و eval/with تعطل التحسين. المحرك جزء من المنصة؛ مواصفة اللغة لا تضمن الأداء.

تقاطع WASM

WebAssembly (٢٠١٧، ١.٠ عبر المتصفحات) شريك، لا منافس. WASM هدف تجميع لـ C++/Rust/Go في المتصفح. JS لا يزال الغراء — WASM لا تلمس DOM مباشرة (مقترح anyref قيد التقدم). نموذج مكونات WASM ٢٠٢٣ ومقترح GC يتجهان لوصول مباشر للمضيف، لكن حتى ٢٠٢٦، JS تظل طبقة DOM الإلزامية لأي تفاعل DOM.

قراءة كود في ٢٠٢٦: إذا رأيت import { something } from 'wasm-module' — الرفع الثقيل في Rust/C++، JS طبقة تنسيق. هذا التقسيم المقصود.

ما JS ليست

  • ليست رياكت → class-to-hooks-paradigm-shift
  • ليست Angular → angular-evolution
  • ليست TypeScript → javascript-across-stacks (تحول TS قصة منافس، لا قصة لغة)
  • ليست الـ ١٢ درس → lessons/ (تلك الآليات؛ هذه الـ لماذا)

أمثلة محلولة — الدلالات وزمن التشغيل في مسار واحد

برنامجان صغيران يمرّسان النموذج من البداية للنهاية. شغّل كل واحد ذهنياً؛ الجواب هو النقطة كلها.

الترتيب: متزامن، مهام دقيقة، مهام كبرى

console.log(1);

setTimeout(() => console.log(2), 0);

Promise.resolve()
  .then(() => console.log(3));

console.log(4);
// 1, 4, 3, 2

لماذا. 1 و4 متزامنان — يعملان حتى الاكتمال أولاً. 3 مهمة دقيقة: تُفرَّغ بعد المهمة الحالية، قبل المهمة الكبرى التالية. 2 مهمة كبرى من المؤقت — تعمل أخيراً، بعد فراغ طابور المهام الدقيقة. الجواب 1, 4, 3, 2. هذه قاعدة الترتيب من النماذج الذهنية للحلقة في مسار واحد: متزامن ← مهام دقيقة ← مهام كبرى ← عرض.

تفويض البروتوتايب مسير زمن تشغيل

const animal = {
  speak() { console.log("generic sound"); },
};

const dog = Object.create(animal);
dog.speak(); // generic sound — delegated up the chain

dog.speak = function () { console.log("bark"); };
dog.speak(); // bark — own property shadows the chain

delete dog.speak;
dog.speak(); // generic sound — the chain is walked again

لماذا. إسناد dog.speak أنشأ خاصية ذاتية حجبت المُفوَّضة؛ delete أزالها واستؤنف مسير السلسلة. لم يُنسخ شيء بين الكائنات في أي نقطة — البحث تفويض (انظر خريطة الدلالات الأساسية). هذا أيضاً سبب أن دوال class التي تتوقع أنها «توجد على النسخة» تعيش فعلياً على البروتوتايب.

مفردات البحث — ما اسم هذه الأشياء

لا يمكنك البحث عن مشكلة لا تعرف اسمها. مصطلحات الفن التي تستخدمها هذه الوثيقة، وكل واحدة منها مفتاح بحث عامل:

  • TDZ (المنطقة الميتة الزمنية) — لماذا ترمي let/const قبل سطر التصريح. ابحث "TDZ JavaScript".
  • التنفيذ حتى الإتمام / حلقة الأحداث — لماذا تنتهي الشيفرة المتزامنة قبل أي استدعاء راجع. ابحث "JavaScript event loop run to completion".
  • مهام دقيقة مقابل مهام كبيرة — ترتيب الوعد مقابل المؤقّت. ابحث "microtasks macrotasks ordering".
  • JIT والأصناف الخفية — لماذا V8 سريعة ولماذا تكذب القياسات الدقيقة. ابحث "V8 hidden classes JIT".
  • IIFE — أسلوب التحجيم قبل الوحدات في الشيفرة القديمة. ابحث "immediately invoked function expression".
  • Tree-shaking — إزالة التصديرات الميتة التي يتيحها هيكل ESM الساكن. ابحث "tree shaking ES modules".
  • خطر الحزمة المزدوجة — نسختان من وحدة واحدة عبر interop بين CJS وESM. ابحث "dual package hazard".
  • تلويث البروتوتايب — مفاتيح غير موثوقة تصل إلى Object.prototype. ابحث "prototype pollution CVE".
  • التحويل والحقيقة الزائفة — القواعد المحددة وراء [] == false. ابحث "JavaScript abstract equality".
  • جذور GC والاحتفاظ — ما يُبقي الكائنات حية؛ آلية التسريب الحقيقية. ابحث "JavaScript memory retention heap snapshot".
