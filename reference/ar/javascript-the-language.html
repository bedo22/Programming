جافاسكريبت: اللغة — التاريخ، التصميم، ونموذج التشغيل

كيف أصبحت JS هي JS: صفقة نتسكيب/صن 1995، سباق برندان إيك في 10 أيام، موكا → لايف سكريبت → جافاسكريبت → إيكماسكربت، نموذج البروتوتايب، حلقة الأحداث، التزامن أحادي المسار، ولماذا أصبحت لغة برمجية نصية لتحقق النماذج هي اللغة الوحيدة التي تعمل أصلياً في كل متصفح. وثيقة تأسيسية لباقي رف المراجع.

لماذا توجد هذه الوثيقة

وثائق المراجع الأخرى (نموذج رياكت، تطور Angular، Next.js العميق، مسح المعسكرات) تعامل JS كمسلمة. هذه الوثيقة تتراجع وتسأل: ما هي JS، ولماذا تبدو هكذا، وما الرهانات التصميمية التي جعلتها اللغة التي تعمل في كل مكان؟ شقيقة لـ ما هي الحالة (التي تغطي نظرية البرمجة عموماً) وسياق أب لـ الانتقال من الكلاسات إلى الخطافات. وثيقتها الشقيقة عبر المنصات (جافاسكريبت عبر المنصات) تغطي أين تعمل JS ومن يحاربها في كل مسار.

٠. كيف تستخدم هذه الوثيقة

ترتيب القراءة: مستقلة. جلسة واحدة. هذه الوثيقة ليست درس JS — الـ ١٢ درس بالفعل هم (النطاق، الإغلاقات، البروتوتايبات، المصفوفات، this، الكائنات، الكيري، السلاسل، الأخطاء، الوحدات، اختبار الشهادة الذاتي). هذه الوثيقة ليست وثيقة رياكت — class-to-hooks-paradigm-shift بالفعل هي. هذه الوثيقة هي القطعة المفقودة: تاريخ اللغة، منطق التصميم، ونموذج التشغيل، مكتوبة لتستطيع قراءة أي قاعدة كود JS دون أن تسأل "لماذا فعلوها هكذا؟" على مستوى اللغة. المرجع: المصطلحات — مفردات مشتركة عبر جميع وثائق المراجع.

١. العشرة أيام في مايو ١٩٩٥

مايو ١٩٩٥. نتسكيب نافيجيتور ١.١ يُشحن. الويب مجرد HTML ساكن. مارك آندريسن يريد المتصفح قابلاً للبرمجة — ليس فقط لعرض المستندات، بل للتفاعل مع المستخدم. يكلف برندان إيك، مبرمج أنظمة عمره ٣٤ سنة انضم لنتسكيب في أبريل، ببناء لغة برمجية نصية للمتصفح. القيود: يجب أن تعمل في المتصفح، يجب أن تكون سهلة لغير المبرمجين (مصممون، مؤلفو HTML)، يجب أن تُشحن في نتسكيب ٢.٠ بحلول سبتمبر.

لدى إيك ١٠ أيام لإنتاج نموذج أولي عامل. يستلهم من خطين:

  • Scheme (Lisp) — دوال من الدرجة الأولى، إغلاقات لفظية، نواة صغيرة. إيك أراد هذا.
  • Java — تحالف نتسكيب/صن يعني "بنية جملة شبيهة بـ Java" كان مطلب إدارة. الأقواس { }، الفواصل المنقوطة ;، new، typeof — كلها على شكل Java.

سُمِّي النموذج الأولي Mocha. شُحن في نسخة بيتا من نتسكيب نافيجيتور ٢.٠ كـ LiveScript. أُعيدت تسميته JavaScript في ديسمبر ١٩٩٥ — مصافحة تسويقية بين صن/نتسكيب: "Java للمؤسسات، JavaScript للمتصفح". الاسم تسبب في ٣٠ سنة من الالتباس. Java و JavaScript تتشاركان البنية (الأقواس المعقوفة) ولا شيء تقريباً غير ذلك.

مصدر أولي → برندان إيك، FAQ: Why is JS designed the way it is? (٢٠١١): "أردت لغة شبيهة بـ Lisp لكن اضطررت لاستخدام بنية جملة شبيهة بـ Java لتمرير موافقة الإدارة. تحت أقواس { } ينبض قلب حساب لامدا في جسد على شكل C."

٢. لماذا لغة جديدة، لا ابليت Java ولا امتداد C++

النظرية التي سألت عنها: لماذا إنشاء لغة جديدة بدلاً من تمديد Java أو C++؟ الجواب هو قيود المنصة.

  • Java applets كانت قادمة بالفعل (١٩٩٥). كانت لديها JVM ثقيلة، خطوة تجميع، كتابة ساكنة، صندوق حماية. كانت لـ تطبيقات داخل المتصفح — ثقيلة، بطيئة البداية، مبالغة لـ "تحقق من هذا النموذج قبل الإرسال".
  • C++ — لا أحد يشحن مترجم C++ لمتصفح. لا تجميع قمامة، إدارة يدوية للذاكرة، لا صندوق حماية آمن. المتصفح يحتاج لغة لا تُسقط العملية.
  • المنصة تحتاج غراء. قشرة برمجية نصية: تحوّر DOM، تتعامل مع أحداث، تحقق نماذج، تتحدث للخادم (لاحقاً: XMLHttpRequest). لغات الغراء مكتوبة ديناميكياً، ذات تجميع قمامة، مفسرة، متسامحة. Java و C++ لا شيء من هذه.

النمط الذي يتكرر: المنصة تستحق لغة مصممة لقيودها، لا ورثة من منصة مختلفة. هذه نفس النظرية التي تبرر لاحقاً TypeScript (ترقية JS لصيانة الفرق الكبيرة، لا بديل)، Go (بديل C++ مصمم للخوادم الشبكية، لا لغة أنظمة عامة)، Rust (بديل C++ يحل أمان الذاكرة بدون GC). القيود تغيرت — اللغة تغيرت.

٣. التصميم: نموذج البروتوتايب، لا الكلاسات

اختار إيك البروتوتايبات لا الكلاسات. التأثير: Self (حفيد Smalltalk، مبني على البروتوتايب، من مختبرات صن). في نظام البروتوتايب، الكائنات تورث مباشرة من كائنات أخرى — لا كلاس ككيان منفصل. تنشئ كائناً، يصبح بروتوتايب لآخرين. Object.create(proto) هو البدائي.

new في جافاسكريبت + دالة منشئة + .prototype طبقة نحوية رقيقة فوق هذا:

// سلسلة البروتوتايب في العمل
function Animal(name) { this.name = name; }
Animal.prototype.speak = function() { console.log(this.name + ' makes a sound'); };

const dog = new Animal('Dog');
dog.speak(); // Dog makes a sound

// dog.__proto__ === Animal.prototype
// Animal.prototype.__proto__ === Object.prototype
// Object.prototype.__proto__ === null

كلمة class في ES6 (٢٠١٥) سكر نحوي فوق البروتوتايبات — لا نظام كلاسات كامل. لا تُدخل حقولاً خاصة (جاءت لاحقاً، ٢٠٢٢)، لا تغير التوريث الأحادي، لا تضيف إرسال متعدد. تخفي التفويض. عندما تقرأ class Dog extends Animal، سلسلة البروتوتايب لا تزال هناك تحته. فهم نموذج البروتوتايب مهم لأن السكر يتسرب: ربط this، استخراج الدوال، Object.getPrototypeOf، __proto__ كلها تكشف الآلية.

٤. التصميم: دوال من الدرجة الأولى، إغلاقات، قلب حساب اللامدا

سلالة Scheme/Lisp. دوال جافاسكريبت قيم — يمكن إسنادها، تمريرها، إرجاعها، إنشاؤها أثناء التشغيل. هذا يمكّن:

  • دوال رتبة أعلى — map/filter/reduce تأخذ دوالاً كمعاملات.
  • إغلاقات لفظية — دالة "تلتقط" نطاقها المحيط. function outer() { let x = 1; return function inner() { return x++; }; } — inner تتذكر x بعد عودة outer.
  • كيري (Currying) — تطبيق جزئي بإرجاع دوال تأخذ المعامل التالي.

هذه ليست "ميزات أضيفت لاحقاً". كانت هناك في النموذج الأولي ذي الـ ١٠ أيام لأن إيك نفذ حساب اللامدا مباشرة. كلمة function هي لامدا. درس الإغلاقات و درس الكيري يغطيان الآليات؛ هذه الوثيقة تغطي لماذا.

مصدر أولي → برندان إيك، JavaScript at 20 (٢٠١٥): "قلب حساب اللامدا كان هناك منذ اليوم الأول. الجسد على شكل C كان التنازل."

٥. التصميم: أحادي المسار + حلقة الأحداث

جافاسكريبت أحادية المسار بالتصميم. مكدس استدعاء واحد. خيط تنفيذ واحد. DOM المتصفح أحادي المسار — خيطان يعيدان رسم نفس DOM سيتسابقان. حلقة الأحداث هي نموذج التزامن:

// while (queue.length) {
//   const task = queue.shift();
//   task();  // تعمل حتى النهاية
//   while (microtaskQueue.length) { microtaskQueue.shift()(); }
//   render();
// }

رهان Node.js (٢٠٠٩): نفس الحلقة تعمل جانب الخادم. لا خيوط لكل طلب — حلقة واحدة، عمليات I/O متزامنة كثيرة. لهذا Node تتعامل مع ١٠ آلاف اتصال على خيط واحد بينما خادم خيوط يحتاج ١٠ آلاف خيط. المقايضة: العمل المكثف CPU يسد الحلقة. الحل: خيوط عاملة (٢٠١٨) أو نقل لعملية أخرى.

٦. بيئة المضيف، لا اللغة

أكبر بصيرة في JS: JS ضيف في مضيف. مواصفة اللغة (إيكماسكربت) تعرف النواة — البنية، الأنواع، الكائنات، الدوال، حلقة الأحداث. المضيف يوفر كل شيء آخر:

المضيفالعموميات التي يوفرها
المتصفحwindow، document، fetch، localStorage، WebGL، WebAssembly
Node.jsglobal، require/import، fs، net، process، Buffer
DenoDeno، Deno.serve، Deno.readFile، APIs قياسية للويب
BunBun، Bun.serve، Bun.file، متوافق مع Node + APIs الويب
Cloudflare Workersfetch، caches، KV، Durable Objects — لا fs، لا net

لهذا window غير موجودة في Node، fs غير موجودة في المتصفح، والكود "الموحد" (isomorphic) ينكسر عندما يفترض عامومية مضيف. اللغة واحدة؛ المضيف يتغير. الدرس: عند قراءة JS غير مألوف، حدد المضيف أولاً. require → Node/CommonJS. import + Deno → Deno. window → متصفح.

١٩٩٦: نتسكيب تسلم JS لـ Ecma International → إيكماسكربت (اسم المواصفة؛ "جافاسكريبت" علامة تجارية).

عملية TC39: المقترحات تمر بمرحلة 0 (فكرة) → مرحلة 1 (مقترح) → مرحلة 2 (مسودة) → مرحلة 3 (مرشح) → مرحلة 4 (مكتمل). تطبيقان مستقلان مطلوبان للمرحلة 4. لهذا الميزات تستغرق سنوات — الويب لا يمكن أن ينكسر.

٨. المحركات: V8، SpiderMonkey، JavaScriptCore

ثلاث محركات، ثلاث سلالات:

  • V8 (Google، ٢٠٠٨) — فئات خفية + تجميع JIT. أيضاً وقت تشغيل Node.js. المحرك الذي جعل JS سريعاً.
  • SpiderMonkey (Mozilla، ١٩٩٥) — أصل إيك. أول محرك JS. لا يزال يشغل Firefox.
  • JavaScriptCore (Apple/Safari، متفرع من KJS) — يشغل Safari، WebKit، و Bun.

لماذا المحركات مهمة للقارئ: JIT يعني خصائص الأداء تعتمد على وقت التشغيل. المقاييس الدقيقة تكذب. "JS بطيئة" قديمة بـ ٢٠ سنة — V8 يجمع المسارات الساخنة لشفرة آلة. لكن: تسخين JIT موجود، وإلغاء تحسين يحدث، و eval/with تعطل التحسين. المحرك جزء من المنصة؛ مواصفة اللغة لا تضمن الأداء.

٩. تقاطع WASM

WebAssembly (٢٠١٧، ١.٠ عبر المتصفحات) شريك، لا منافس. WASM هدف تجميع لـ C++/Rust/Go في المتصفح. JS لا يزال الغراء — WASM لا تلمس DOM مباشرة (مقترح anyref قيد التقدم). نموذج مكونات WASM ٢٠٢٣ ومقترح GC يتجهان لوصول مباشر للمضيف، لكن حتى ٢٠٢٦، JS تظل طبقة DOM الإلزامية لأي تفاعل DOM.

قراءة كود في ٢٠٢٦: إذا رأيت import { something } from 'wasm-module' — الرفع الثقيل في Rust/C++، JS طبقة تنسيق. هذا التقسيم المقصود.

١٠. ما JS ليست

  • ليست Angular → angular-evolution
  • ليست TypeScript → javascript-across-stacks (تحول TS قصة منافس، لا قصة لغة)
  • ليست الـ ١٢ درس → lessons/ (تلك الآليات؛ هذه الـ لماذا)

١١. النظام الإيكولوجي — كتالوج الأدوات مع معايير القرار

اللغة جيدة فقط بقدر الأدوات التي تجعل دلالاتها مرئية، قابلة للاختبار، وقابلة للترحيل. يسرد هذا القسم فئات الأدوات الأساسية، مع معايير قرار لكل منها.

الفئةالأدوات / المنصاتالمُحفّز → الهدفمقاييس القرار

طريقة اختيار: ابدأ بالتدقيق + فحص الأنواع + الاختبار ("مجموعة أدوات JS الدنيا القابلة للحياة"). أضف التجميع عندما وقت البناء >٣٠ث أو حجم الحزمة مهم. أضف التحليل الثابت عند عدد التبعيات >١٠٠. أضف ملف الأداء عندما p99 زمن الوصول > الميزانية. أضف أدوات الهجرة عند عدد أنماط >٥ عبر قاعدة الكود. الأداة تخدم اللغة — لا العكس.
