This is a **strong, practical doc**. It correctly treats hiring as a **funnel and risk-assessment process**, not as a mysterious ritual. The framing — “answer the risk, not the costume” — is excellent, and the remote/async interview section is especially valuable for your context.

The doc is strongest on:

- the end-to-end funnel from application to onboarding,
- HR/behavioral questions decoded as risk pricing,
- remote/async interview mechanics,
- the worked example,

## 3.4 Missing: technical screen tactics

The doc says “think out loud, plan before code, correctness first,” which is correct, but it should expand into a concrete playbook.

Add:

### Live coding playbook

1. **Clarify the problem**
   - What is the input?
   - What is the output?
   - What are edge cases?
   - What constraints matter?

2. **Restate it**
   - “So the goal is to return the first non-repeating character, case-sensitive, and return null if none exists?”

3. **Start brute force**
   - A correct O(n²) solution beats a broken O(n) solution.

4. **Explain complexity**
   - “This is O(n²) because of the nested loop. I can improve it with a hash map to O(n).”

5. **Implement**
   - Keep it readable.
   - Name variables clearly.
   - Avoid premature optimization.

6. **Test**
   - Empty input
   - Single element
   - Duplicates
   - Large input
   - Invalid input

7. **If stuck**
   - Say what you are considering.
   - Try a concrete example.
   - Simplify.
   - Ask whether your direction is reasonable.

This is directly aligned with Problem-Solving but stays interview-specific.

## 3.11 Missing: negotiation scripts
