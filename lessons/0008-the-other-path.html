The Other Path — Angular's Evolution, for Contrast

React's class→hooks arc (Lesson 6) is one camp's story. Angular took a different path to the same destination — narrower watching. Three eras, one name, each rewriting reactivity from scratch. Anchored to Angular's Evolution.

Where this fits

Lesson 7 was the universal thinking loop. This is a contrast: the same period (2010–2026), a different framework, a different mechanism for the same goal. It pairs with Lesson 6 (React's arc). Next, Lesson 9 returns to React's frontier. See the plan.

1. Three frameworks, one name

Angular is not one framework. It is three frameworks with the same name, each rewriting the state and reactivity model from scratch. There was no gradual migration between them — AngularJS apps had to be rewritten entirely to become Angular 2 apps. The three eras:

  • AngularJS (2010–2016) — $scope tree, dirty-checking. A "digest cycle" walked the whole tree comparing old vs new values on every interaction.
  • Angular 2+ (2016–2023) — class components, TypeScript, dependency injection. zone.js monkey-patched browser APIs and broadcast "something changed" to all components, running change detection.
  • Modern Angular (2023+) — Signals, standalone components, zoneless. A fine-grained subscription graph triggers only the components that depend on a changed signal.

Notice the direction: each era widened the developer experience and narrowed what the framework had to watch — from the whole $scope tree, to all components on every async event, to just a signal's dependency graph.

2. Era by era — and why each gave way

AngularJS (2010) solved the same problem as Backbone and Ember: make the page dynamic without hand-writing DOM code. Its dirty-checking digest cycle walked the entire $scope tree, comparing old vs new values on every interaction. It worked — until apps grew. Thousands of watched expressions caused visible lag on every keystroke. The architecture couldn't be fixed incrementally.

Angular 2+ (2016) was a from-scratch rewrite: class components, TypeScript, dependency injection, and zone.js as the change-detection engine. Zone.js monkey-patched browser APIs so that any async event broadcast "something changed" to all components, which then ran change detection. Stable for a decade — but the cost was a 0% migration path: AngularJS apps had to be rewritten entirely, which created the "Angular 1 → anything else" migration wave of 2016–2019.

Modern Angular (2023+) adopted Signals (signal(), computed(), effect()), standalone components, and a zoneless mode. A signal builds a fine-grained subscription graph, so a change triggers only the components that depend on that signal — not all of them. The watching got minimal.

3. The contrast with React — same direction, different mechanism

Here's the headline. React and Angular both moved in the same direction — narrow what the framework watches — but by a different mechanism:

  • React narrowed the component's awareness of what changed: this.setState (you tell it) → hooks deps arrays (you list what an effect depends on) → the compiler (it infers for you).
  • Angular narrowed the framework's watching: the whole $scope tree → all components on every async event → a signal's dependency graph.

That difference also explains the Signals question. Angular adopted Signals; React declined. Not because one is "better," but because they had different bottlenecks. Angular's bottleneck was zone.js broadcasting to everything — Signals' fine-grained graph fixed that. React's bottleneck was the manual deps-array tax — and the compiler fixed that without changing the per-render capture model that Signals would have broken. Same diagnosis (the framework reacts too broadly), different treatment.

The win

  
You now hold Angular's arc as a contrast to React's: three eras, one name — AngularJS (dirty-checking), Angular 2+ (classes + zone.js), Modern Angular (Signals + zoneless) — each rewriting reactivity from scratch, with a 0% migration path between them. The headline: React and Angular moved in the same direction (narrow what's watched) by a different mechanism — React narrowed the component's awareness, Angular narrowed the framework's watching. And Angular took Signals where React took the compiler, because they had different bottlenecks. At work you can place Angular code without forcing React's model onto it.
