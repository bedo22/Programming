The Frontier — React 2024+ & Next.js

The class→hooks story (Lesson 6) settled the component model. What happened next: a compiler that auto-memoizes, Server Components that split rendering across two computers, and a framework layer that's now the default. Anchored to React 2024+ and Next.js Deep Dive.

Where this fits

This is the Practice finale, and it completes the React story begun in Lesson 6. The mental model from Lesson 6 still holds — the compiler and Server Components are layers on top, not replacements. Next, the journey enters the System movement: API design (Lesson 10).

1. What happened after hooks settled

By 2024, the function+hooks model from Lesson 6 was settled — useState, useEffect, closures capturing values per render. The React team's attention moved up-stack: two big additions and one big recommendation.

The two additions: a compiler that removes the last hooks-era friction (manual memoization), and Server Components that split rendering across two computers. The one recommendation: Create React App was sunset in February 2025 — new apps should use a framework, not bare React. Together these define the frontier you'll read at work.

2. The compiler finishes what hooks started

Recall Lesson 6: hooks gave functions state and effects, but left one tax — manual memoization. To keep a value or function stable across renders you reached for useMemo, useCallback, or React.memo, and got the deps arrays right by hand. The React Compiler v1.0 (stable, October 2025) removes that tax. It's a Babel plugin that analyzes your code's data flow and mutability, then inserts memoization automatically — even in places useMemo can't legally go, like after an early return.

For you, reading code at work: useMemo, useCallback, and React.memo become escape hatches, not the default. New code written under the compiler can be the simple version — a plain function with hooks, no manual memoization, no wrapper components — because the compiler puts the optimization back. Existing code keeps working; you don't have to rip out old memoization to adopt it. The Lesson 6 mental model is untouched; the compiler just lifts the chores off it.

3. Server Components split the process across two computers

The second addition is bigger in shape. React Server Components (RSC) split rendering across two computers:

  • Server components run once on the server. They fetch data, talk to the database, and send HTML to the client. They have no hooks, no events, no interactivity — they're pure data-to-markup.
  • Client components run in the browser with the full hooks model you learned in Lesson 6 — useState, useEffect, closures capturing values per render. The directive "use client" at the top of a file marks the boundary.

This is why Next.js is now the framework you're most likely to meet on a React job. Next.js is React plus routing, the server/client split, caching, and tooling. Its App Router defaults to Server Components; you opt into the client model with "use client" where you need interactivity. And in February 2025, React's team sunset Create React App and made it official: new apps should use a framework — Next.js, React Router (in framework mode), or Expo — not bare React. The component model is settled; the next layer is the framework.

The win

  
You now hold React's frontier: the compiler (stable, Oct 2025) auto-memoizes, so useMemo/useCallback become escape hatches — you write the simple version and it puts the optimization back. Server Components split rendering across two computers — server components are data-only (no hooks, no events), client components get the full Lesson 6 model, and "use client" marks the boundary. And Create React App was sunset (Feb 2025) — new apps use a framework, with Next.js the most likely on a React job (App Router defaults to Server Components). The big reassurance: the Lesson 6 model still holds — the compiler and RSC are layers on top, not replacements.
