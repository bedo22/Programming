# 0021 — Upstream of code: Design Thinking discovers the problem, and design theater is its failure

**Date:** 2026-08-06
**Lesson:** `lessons/0021-upstream-of-code.html`
**Reference:** `reference/design-thinking.html` §1, §3, §8, §10

## Context
The second lesson of the Human/product movement. Design Thinking is the layer *upstream* of everything technical — it answers "what problem is worth solving, for whom?" before code, before UI (L20), before system design (L11). For the learner's exploration mission, it completes the vertical stack: the full journey has built from the atoms (L1–3) up through system (L10–11) to the process (L18–19) and now the human layers.

## Key insight
Every Design Thinking method serves the **desirability / feasibility / viability Venn** (IDEO): a product lives in the intersection, and each empty circle gives a distinct failure mode. The most important for this journey: *feasible + viable but not desirable* = "a solution in search of a problem" — you built the wrong thing perfectly, the very thing the whole engineering journey guards against. The five phases (Empathize → Define → Ideate → Prototype → Test) are a rhythm, not a waterfall. The one failure mode to never forget: **design theater** — method without empathy — ritual that produces no decision and no change.
