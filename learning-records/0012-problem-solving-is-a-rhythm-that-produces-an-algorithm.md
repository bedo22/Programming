# 0012 — Problem-solving is Pólya's four phases, a rhythm that produces an algorithm

**Date:** 2026-08-04
**Lesson:** `lessons/0012-problem-solving-polyas-four-phases.html`
**Reference:** `reference/problem-solving.html` §1–§2

## Context
The learner asked whether the "Rhythm" reference covers problem-solving. It doesn't — the rhythm reference covers the frontend feature loop (Model→View→Flow), not general problem-solving. Research revealed a missing layer: the three-layer model (Design Thinking → Problem-Solving → The Rhythm). The learner's own HackerRank comment (Input/Operation/Output + numbered algorithm) was already doing Pólya's Phase 1 and Phase 2 — two-thirds of the framework — without knowing its name.

## Key insight
Problem-solving is a **rhythm (Pólya's four phases) that produces an algorithm (the specific solution)**. The rhythm is the process; the algorithm is the product. The difference between a HackerRank challenge (well-defined → algorithm) and a React feature (wicked → rhythm) is the problem type, not the thinker. Both use the same four phases.

## What was missing from the learner's intuition
- **Phase 4 (Look back)** — the edge cases, the "can I derive it differently?", and pattern filing. The phase everyone skips, and the one that builds the most long-term skill.
- **The vocabulary** — the learner was doing the right things (decomposition, abstraction, specialization, hash table paradigm) but didn't know the names.
- **The three-layer model** — positioning problem-solving as the missing middle between Design Thinking and The Rhythm.
